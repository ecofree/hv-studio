# 风趣历史 · Writing-DNA v5.1

生效日期：2026-11-17。入口与资产状态见 [README](README.md)。本文件是本目录唯一总规范；四份专项规范须遵守本文件，旧版规则与历史范例不再覆盖它。

## 1. 核心风格与优先级

像一位见多识广、讲得明白的说书人：用日常话解释兵粮、官位、亲缘、制度和选择的代价；让幽默来自情境，让人物保留复杂性。观众不需要先懂官制，也不该被当成等待训导的人。

发生冲突时，优先级为：**证据边界 → 清楚好懂 → 具体场景 → 幽默与修辞**。写不出有依据的现场动作，可以讲关系、选择和后果；不补汗水、眼神、手势、天气、密室对白来满足戏剧要求。已画好的场景也不能反过来证明历史。

不要求笑哭比例、比喻递减比例、固定字数、固定集数、固定三连句、必然悲剧结尾。词频只帮助发现复读；“不是……而是……”等正常语法不是自动删稿依据。标题、首帧、旁白和结尾应回答同一个问题，不用确定性的定罪标题包装尚有争议的结论。

## 2. 史料与主张

每个关键事实、引语、数字、死因、动机论证都有可回查的 `claim_id`。主张记录至少包括：口播表述、来源书名/卷页或条目、版本和链接、必要短摘、核查日期、主张类型、争议/反证、允许的画面表达与核查状态。具体方法见 [写作视角与认知框架](写作视角与认知框架.md)。

必须区分：史籍记载、史籍指控、现代研究解释、作者推论、艺术示意、未知。史书写了某事，不等于该事已被独立证实；成书早晚、正史或笔记类别均不能单独给出真伪结论。诗文可作解释线索，不能一律当作内心动机的实证。

引号内原文逐字回查并注明出处；翻译/口语改述用间接引语，不把自己的大白话署到古人名下。多部史书不能拼成一条“共同原句”。缺乏记载不能直接写成“从未”“没有调查”；“最后一句”“所有人”“当天”一类强断言应单独检查。

语言示范使用 [语言DNA](语言DNA.md) 的三组短例，均注明原典与已有核查范围；不要从旧稿、清洗语料或竞品报告自动提取事实。

## 3. 故事与口播工作流（文件驱动三阶段解耦架构）

长视频创作（15–45分钟，按 100字=1条事实原子 动态定长，全剧 14–18 幕，单幕 500–600 字，上限 12,000 字以内）**严禁通过把单幕拉长到 1,000 字以上来凑时长（单幕死守 500–600 字快刀节奏，平均每条事实最多展开 115 字，杜绝车轱辘话注水）**，**严禁“同屏自导自演”伪造审校**。必须以**磁盘落盘文件为物理硬边界**，按三个独立阶段解耦推进，从底层阻断学术考据腔与文言概率对说书语感的污染：

### 阶段一：史料锁定与叙事骨架（Pass 1 · 工程师模式）
- **输入**：选题范围、原始文言史料、事实争议。
- **事实配额铁律**：严格执行 **“100字正文 = 至少 1 条独立历史事实原子”**（15分钟常规集需 $\ge 35$ 条事实；40分钟超长特辑需 $\ge 85$ 条事实）。严禁靠形容词和车轱辘话拉长时长。
- **超长篇（>30分钟 / >8,000字）分拆铁律**：先运行 **Pass 1A** 输出《3–4 大篇章总控提纲与事实配额表》；再按篇章分批运行 **Pass 1B**，每次只深挖 1 个篇章的 22–28 条白话事实原子，防止单次输出过长导致干货被压缩。
- **动作**：输出结构化文件 `pass1_facts.json`（及可读提纲），包含：
  1. `master_clock`：全片倒计时时钟与核心赌注；
  2. `verified_quotes`：原典逐字短引语白名单（供后续脚本校验双引号）；
  3. `fact_atoms`：分幕白话事实原子数组（每条含 `claim_id`、史源限定语、数字/器物/动作真细节、以及本幕的**“荒诞反差 / 迷之自信时刻”**）；
  4. `red_lines`：史料未载禁区与争议分歧点。
- **物理隔离铁律**：文言原句封存后台，严禁带入 Pass 2 上下文！

### 阶段二：沉浸式说书人写稿（Pass 2 · 创作者模式）
- **输入**：只能加载 `pass1_facts.json` + `语言DNA.md` + `文章结构模板.md`。严禁加载原始文言底表！
- **长视频“分幕分段接力”铁律**：
  - 无论 15 分钟还是 40 分钟，**每次只生成 2 幕（严格控制在 800–1,100 字，单幕 500–600 字）**，追加写入 `pass2_draft.md`。
  - 每次接力仅输入：`当前 2 幕的白话事实原子` + 一张不超过 150 字的 **《滚动状态卡》**（当前时钟刻度、在场人物与4–6字身份标签、未爆伏笔、上一幕尾句）。
- **语言与格式执行准则**：
  - 严格执行 `语言DNA.md` 的**快刀冷幽默 + 口语润滑词**铁律，60 字内必有新动作或局势反转。
  - 严禁把“第一大篇章在此完成结算”等结构提示词写进朗读正文！
  - 每幕头部格式必须严格写死为三行（严禁改写为 Markdown 列表 `* **视听构图**`）：
    ```text
    ### 【第X幕：幕标题】
    【视听构图：...】
    【语气：...】
    ```

### 阶段三：代码门禁拦截与红线审校（Pass 3 · 审稿人模式）
- **前置硬门禁**：在审校前，必须先运行 `python tools/script_linter.py pass2_draft.md pass1_facts.json`，获取客观报错列表。
- **防误杀护栏**：凡在 `pass1_facts.json` 中有明确来源锚点的具体动作、器物与基于事实算账的冷面幽默，一律保留白描，严禁误杀。
- **挑刺 diff 审校（禁止输出“全部达标”总结表）**：默认初稿存在问题，逐幕输出 `【修改前 → 修改后】` diff 清单，重点清理：1) 无据生理/心理脑补；2) 不在 `verified_quotes` 白名单内的双引号台词及冒号第一人称变相台词；3) 相邻段落车轱辘话重复与结尾排比说教；4) **第四刀（核对人物生死与官制时代）**：逐一对照 `pass1_facts.json` 的 `entity_fate_ledger` 与 `anachronism_and_date_guard`，确保俘虏没被误写成阵亡、普通诀别酒没被误写成“饮鸩”、后世官名（如户部、十二卫）没有提前穿越。
- **终验放行**：修订后保存为 `narration_final.md`，再次运行 `python tools/script_linter.py narration_final.md pass1_facts.json`，**返回退出码 `0` 后**，方可执行交接指令。

## 4. 正文、TTS、导演信息的交接

**唯一正文权威**：生产选择的明确版本和哈希是内容权威。剧本正文与画面字幕**必须 100% 保留标准规范汉字**（如“裴行俭”“吐蕃”“李恪”“单骑”），严禁在正文写作阶段写入同音错别字。字幕回到同一正文。

**派生 TTS 文本层与多音字工程门禁**：发音需求全部统一收口至后置 `phonetic_engine.py` 自动化处理。在送入 TTS 引擎前，由系统通过词库自动将高危词映射为单音字（如“裴行俭”转“裴形俭”）；**该替换结果仅存在于内存/派生TTS文本流中，严禁回写至正文或字幕文件！**

**锁定导演标注与 Parser 边界**：
- 画面、构图、语气和停顿独立于口播正文。正文中的 `【视听构图】`、`【语气】` 标注以及画面叠加层“公元纪年口播 + 年号进字幕角标”的非朗读信息，交接时必须严格遵循当前 parser 的规范标注格式。
- **音频流防穿帮铁律**：严防任何画面提示词、导演标注或角标年号混入 `phonetic_engine.py` 的音频合成流里被当成正文读出来。
- **语法死锁**：每幕的导演标注必须独占一行且使用中文全角方括号（`【视听构图：...】` 与 `【语气：...】`），严禁写成 `* **视听构图**：...` 等 Markdown 列表格式，否则 parser 无法剥离，会导致 TTS 直接将画面提示词朗读进音频中。

**声音表演**：说明说给谁、句子的意图、重词、语速趋势、停顿和强弱。块大小由引擎限制、句义和实际试读决定，单切片安全粒度保持在 320~420 汉字。

**画面与时间轴**：固定画风、人物和音色继续沿用。画风唯一权威为 `profile.image.style_suffix` 与 `negative_clause`。时间轴字幕卡展示规范历史年号与公元年份（如 `公元618年 · 唐武德元年`），口播语音严格念公元纪年或相对时间。

## 5. 验收与保留

- 内容：关键主张可回查；引语原样；争议传递到标题、画面和字幕；每幕回答核心问题的一部分。
- 交接：正文、TTS和字幕可对齐同一输入；导演标注有逐条去向；换稿后旧音频/图像/时间轴不会冒充新稿证据。
- 视听：按 [视觉风格指南](视觉风格指南.md) 做逐幕设计，完整试听看审，记录问题时间点和归属工序。不得将测试通过称为艺术批准。
- 保留：旧稿、原录音、已批准素材、图像缓存均保留；新版本独立交付。清洗库原字节不变，清理和去重有范围、原因和哈希。
- 技术：运行项目所需检查并保留当前源码与输入绑定证据。技术候选、事实复核、艺术判断和发布决定分别记录。
