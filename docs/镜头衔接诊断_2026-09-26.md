## 结论

音画同步不是问题：逐镜「json 记录时长 vs 磁盘 wav 真实时长」误差为 0，累计漂移 ≤2ms，视频总时钟与音频总时钟完全相等；分段帧数相加等于成片帧数，无丢帧。

问题是运镜在剪辑点不连续。`app/services/shot_builder.py` 给每一镜独立分配 `start_zoom`/`start_xy`，只按「scene 内第几帧」查固定阶梯、按全局帧号轮换运镜类型，从不读取上一镜的结束状态：

- `shot_builder.py:222` — `zoom = 1.0 if j == 0 else ZOOM_LADDER[(j-1) % len(ZOOM_LADDER)]`
- `shot_builder.py:43` — `ZOOM_LADDER` 被 `max_zoom: 1.15` 截断，`[1.12,1.26,1.40,1.18,1.32,1.08,1.22]` → `[1.12,1.15,1.15,1.15,1.15,1.08,1.15]`，7 档塌成 4 个值
- `shot_builder.py:189-197` — `_next_motion` 只禁止「连续同型」，不延续机位方向
- `shot_builder.py:200-207` — `_build_motion` 每镜从零重设 `start_xy`/`start_zoom`

后果：同一场景跨多帧时（占全部剪辑点约三分之二），每次内部切换裁切窗都会瞬移，最严重的两种切换是 `pull→pan` 和 `drift→pull`，因为它们同时重置 zoom 与 pan 原点。
