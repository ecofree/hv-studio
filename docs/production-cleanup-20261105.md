# 第三集生产复盘与清理（2026-11-05）

结论：存在旧入口没有退出、生产路径与状态展示脱节、错误修复缺少真实失败回归的情况；不能把全部问题归咎于旧代码。本次执行者反复开新额度、修改未被消费的输出文件、使用运行时替换函数，同样造成了无效调用。

## 生产证据

第三集预算账本合计 147 次图片调用：84 成功、63 失败或结果不确定。成片采用 84 张新图和 4 张复用图。没有把失败次数重置或当成退款。本次清理没有新增供应商调用。

## 已修复

- 批量调度轮转全部渠道，健康度只展示未用于该路径：在发送前排除已不健康的渠道；全部不可用时停止，恢复走明确的服务恢复操作。
- 单渠道运行保存健康记录会删除其他渠道历史：文件锁下合并历史，保留未参与的渠道，移除未使用的信号量字段。
- 中文内容拒绝与普通 HTTP 400 未形成持久停止记录：保留 HTTP 状态码并停止原请求的自动换路/重发；新预算不能绕开同一请求的停止记录。
- 503 被错误标记为已收到图片响应：改为冷却失败渠道后尝试其他健康渠道，仍由原预算限制实际请求数；收到响应或结果不明仍停止重发。
- 编辑生成目录提示词不影响下一次请求：正式支持 production/v2/source_image_briefs.json，绑定 source_sha256；en 只描述场景，由统一配置补画风。重启后使用同一输入，原 storyboard 快照继续是输出。
- 第三集 5 个修订提示词迁入正式输入；五个请求指纹均与现有已使用图片匹配。移除运行时替换函数脚本。
- 验收脚本自行加入 tools/ffmpeg/bin，消除因调用环境未配 PATH 导致的伪回归。
