# CosyVoice 情感控制手段全览（2026-09-08 实测）

> 回答「如何能确保音频有感情」。全部结论来自**本项目实测**（v3.5-plus +
> hvndrama 设计音色），不是文档摘抄；文档与实测冲突处以实测为准。

---

## 一、CosyVoice（v3.5-plus）全部可用的控制手段

| # | 手段 | 粒度 | 确定性 | 本项目现状 |
|---|---|---|---|---|
| 1 | **音色描述**（voice design prompt） | 全片 | 确定 | ✅ 已用（hvndrama） |
| 2 | **instruction** 自然语言指令 | 每次请求 | ❌ **不可控** | 已用 → **问题来源** |
| 3 | **SSML `<speak rate pitch volume>`** | **逐句** | ✅ 确定 | 未用（实测有效） |
| 4 | **SSML `<phoneme>`** 拼音+声调 | **单字** | ✅ 确定 | 未用（实测有效） |
| 5 | **SSML `<break>`** 精确停顿 | 任意位置 | ✅ 确定 | 未用（实测有效） |
| 6 | SSML `<sub>` 文本替换 | 词 | 确定 | 未用（可替代 polyphone） |
| 7 | 全局 rate / pitch / volume | 全片 | 确定 | pitch 弃用（09-03 实测发闷） |
| 8 | seed 随机种子 | 全片 | 可复现 | 未用 |

**instruction 的局限（本项目实测）**：
- 长度上限 100 字符（汉字按 2 计）—— 当前指令 47 字已接近上限
- **组间不一致**：55 组实测 F0 88~186Hz、语速 2.8~4.8 字/秒
- **段首副作用**：「段首 + 生僻专名 + 指令」会念糊（尉迟恭为后院）
- 它是"提示"，模型怎么理解不受控 → **无法保证一致性**

## 二、SSML 实测结果（决定性）

### 1. v3.5-plus 支持 SSML ✅
官方 SSML 专页写「仅适用于 v3-flash/v3-plus/v2」，与另一页矛盾。
**实测：v3.5-plus + 声音设计音色，SSML 全部生效。以实测为准。**
（调用方式：HTTP 非流式接口 + `enable_ssml: true`，音频从返回的 URL 下载；
SDK 的 `SpeechSynthesizer.call()` 不带 enable_ssml 参数，需改走 HTTP 或查 SDK 新版）

### 2. `<phoneme>` 拼音精确控制多音字 ✅（plus 与 flash 均验证）
```xml
<speak>七十万<phoneme alphabet="py" ph="dan4">石</phoneme>粟米装上大车。</speak>
```
- 实测：基线读「70万**时速**米」（石→shí ❌），加 phoneme 后读「70万**担**粟米」✅
- **flash 同样生效**（2026-09-08 补测）：flash 基线「70万时速米」→
  phoneme 后「70万**担**粟米」✅
- 这直接替代整个 polyphone「同音字替换」方案 —— 不用再把字幕文本改掉，
  显示与读音彻底解耦
- 适用：石(dan4)、顷(qing3)、槊(shuo4)、尉迟(yu4 chi2)、可汗(ke4 han2)…
- ⚠️ 顷(qing3) 实测未改善（两顷 连读仍糊），需进一步测是标注方式还是模型问题

### 2.1 flash vs plus 的 SSML 对比（2026-09-08 补测）

| 测试 | plus | flash |
|---|---|---|
| `<speak>` 包裹 | ✅ | ✅ |
| `<phoneme>` 石→dan4 | ✅ 担 | ✅ 担 |
| `<break>` | ✅ | ✅ |
| 多个 `<speak>` 并列 | ✅ | ✅ |
| rate 单调性 | 1.0→6.0s / 0.8→6.8s / 0.6→7.9s | 1.0→6.0s / 0.8→6.7s / 0.6→7.8s（一致）|
| pitch 上调 1.15 | — | F0 148→174Hz ✅ |
| pitch 下调 0.85 | — | F0 152Hz（几乎没降，⚠️ 不对称）|

**结论：SSML 能力 flash 与 plus 相同**，差别只在音质与价格
（flash ¥0.8/万 vs plus ¥1.5/万，14.6min 片 ¥0.29 vs ¥0.54）。
注意 flash 的 `<speak>` 包裹会轻微改变断句（「70万时，粟米」），
建议 phoneme + speak 一起用。

### 3. `<break>` 精确停顿 ✅
```xml
<speak>…唯一选择<break time="600ms"/>把自己的两个嫡子，</speak>
```
破折号不再需要「替换成逗号」这种妥协。

### 4. 逐句韵律 = **受控的起伏** ✅（最关键）
```xml
<speak rate="1.0" pitch="1.0">平缓叙述的句子。</speak>
<speak rate="0.82" pitch="0.92">紧张压抑的句子，放慢压低。</speak>
<speak rate="1.08" pitch="1.06">高潮句，加快抬升。</speak>
```
实测同一句：rate 1.0→6.0s、0.8→6.8s、0.6→7.9s（单调、可复现）。
支持多个 `<speak>` 并列（不允许嵌套）。

**这就是「确保有感情」的答案**：起伏不再是模型对指令的自由发挥，
而是**逐句写死的确定性标注** —— 同样的输入永远得到同样的输出，
组间不会漂移，也不会有某段突然变成另一个人。

---

## 三、为什么 instruction 会「起伏不准确」

instruction 是对**整次请求**的提示，模型自行决定在哪里停顿、压低、加重。
55 组各自独立请求 → 各组对同一条指令的理解不同 → 组间漂移。
（对比：SSML 是逐句写死的参数，天然一致。）

## 四、建议的最终架构（SSML 路线）

```
剧本 script.md
  └─ 每段【导演标注】/ 情绪标记
       └─ 生成 SSML：逐句 <speak rate pitch> + 多音字 <phoneme>
                     + 关键停顿 <break>
            └─ cosyvoice-v3.5-plus（不传 instruction）
                 └─ 段落级合成 → 切回逐帧
```

| 现有补丁 | SSML 路线下的归宿 |
|---|---|
| polyphone 同音字替换 | 换成 `<phoneme>`（显示与读音解耦，更干净） |
| 破折号替换成逗号 | 换成 `<break time="600ms"/>` |
| instruction 全局指令 | **删除**（不一致的根源） |
| 易错词表 + 逐帧降级 | 不再需要（phoneme 直接钉死读音） |
| ASR 回检 | 保留（最后一道质检） |

## 五、实施代价与风险

| 项 | 说明 |
|---|---|
| 代码改动 | 中等：新增 SSML 生成器（文本+标注→SSML）；合成入口改走 HTTP（SDK 不带 enable_ssml） |
| 数据 | 需要一份「逐句情绪标注」——可从剧本【导演标注】提取，或按标点/情绪规则自动打标 |
| 成本 | TTS ¥0.54/次（与现在相同）；调试期几次 A/B ≈ ¥0.5 |
| 风险 | ① 顷(qing3) 那类 phoneme 未生效的case需再测；② SSML 走 HTTP 而非 SDK，要处理 URL 下载/重试；③ 官方文档对 v3.5 的 SSML 支持说法不一，存在未来版本变更风险 |

**建议先做一次 200 字的 SSML vs 现状 A/B**（成本 ≈ ¥0.1）：
同一开篇段落，一条用 instruction，一条用逐句 SSML 标注，你听完再定。
