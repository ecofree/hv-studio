# 审计 #7：hv 全环节合理性审计（2026-09-05）

口径：只读审计，未改任何代码。每条发现均有 文件:行号 证据。
范围：orchestrator / script / image / shot_builder / compose / voice / polyphone /
timing_assert / motion / config / models / managers / controllers / webui /
cli / bin / tests / git 卫生 / 磁盘卫生。
测试基线：92 用例全绿（分块跑，各用全新 basetemp）。

先说结论：**防护网已经相当密**（帧指纹门禁、逐镜求和口径、原子改名、超时收口、
wav-vs-json 校验、transient 重试、prompt 预筛、cost 台账、count_packets 校验），
剩下的问题集中在四类：**双轨遗留、双头常量、死代码、卫生**。

## P0 —— 影响正确性 / 钱 / 安全

### P0-1 API 付费端点零鉴权，唯一防线是绑定地址
- 证据：`app/controllers/v1/image.py:22` `POST /v1/image/test` 直接付费生图；
  `app/controllers/v1/episode.py:31` `POST /v1/episode/{id}/produce?stage=assets`
  可触发 TTS+生图双付费；`episode.py:23-28` `POST /{id}/init` **无条件 `save()`
  覆盖**已有 episode.json。全部无鉴权。
- 现状兜底仅是 `--host` 默认 127.0.0.1（cli.py:287）+ CORS 白名单。一旦
  `--host 0.0.0.0` 就裸奔。
- 建议：加一个 token 头校验（env `HV_API_TOKEN`，存在才启用），三个端点先加；
  或至少把 `/init` 改成「已存在则 409」。

### P0-2 TTS 失败默认静默换成另一种声音，且无瞬时重试
- 证据：`app/services/voice.py:263-266`——cosyvoice 失败且 `fallback_to_edge=True`
  （默认）→ 降级 edge-tts。edge 与 cosyvoice 是**完全不同的音色**，一部 20min
  片子中间换人，日志只有一行 print，成片无任何标记。
- 对照：生图在 2026-09-04 已有 transient 分类 + 同渠道重试；**TTS 没有**
  （429/超时直接判失败 → 走降级）。TTS 同样花钱。
- 建议：① cosyvoice 加瞬时重试（复用 `is_transient_error` 思路）；
  ② 降级 edge 后在该 frame 上打标（如写进 manifest `engine: edge`），
  compose 或 verify 时汇总「本片有 N 帧音色不一致」；③ 交付集生产建议默认
  `--no-fallback`，宁可失败也不混音。

### P0-3 双轨生产链并存：CLI 同时活着 `run`（旧 M2）和 `produce`（新）
- 证据：`app/cli.py:40-55`——`episode run` 调 `managers/pipeline.run_episode`
  （M2 编排器，带 face_sim 门控），`episode produce` 调 `orchestrator.produce`。
  两条链都会实际执行。`run_stage` 状态机（managers/episode.py:216-271）+ checkpoint
  机制只被旧轨和测试引用，`produce` 完全绕过它自己手写状态导出。
- 风险：两个入口对「已完成」的判定口径不同，误用旧轨可能按旧语义覆盖产物；
  checkpoint 在生产路径不产生，出问题无法回滚。
- 建议：二选一。推荐保留 `produce`，把 `run` 标记 deprecated（打 warning）或
  删除 `pipeline.py`；若 `run --only shot-xxx` 的单镜重建能力还想留，把它
  收进 orchestrator 作为一个 stage。

### P0-4 根 `config/` 是僵尸目录，且与 `app/config/` 有同名文件
- 证据：根 `config/`（models.yaml / polyphone.yaml / voices.yaml / style.yaml）
  **无任何 Python 代码读取**（全仓 grep 为零），是 MoneyPrinterTurbo 骨架遗留。
  但 `polyphone.yaml` 在根目录和 `app/config/` 各有一份——活的是
  `app/config/polyphone.yaml`（polyphone.py:17）。
- 风险：要加多音字规则时极易改错那份，改了根目录的不生效，排查半小时。
- 建议：整个根 `config/` 删除（或并入 app/config 后删除）。

## P1 —— 设计缺陷 / 漂移风险

### P1-1 HEAD_MS/TAIL_MS 三处复制，FPS 两处复制
- 证据：`compose.py:41-42`、`shot_builder.py:48`（注释自己写「需与 compose 一致」）、
  `timing_assert.py:26-27` 三份 100/150；`motion.py:51` 与 `timing_assert.py:25`
  两份 FPS=25。
- 这正是坑 #8「双头漂移」的同型。此前 MIN_FRAG_CHARS 手写魔数的教训刚修完，
  这几处是同构隐患。
- 建议：以 compose.py 为唯一真源，其余 import。

### P1-2 字幕参数硬编码，config.yaml 的 subtitle 段形同虚设
- 证据：`compose.py:77-84` `FONT_PATH="C:/Windows/Fonts/NotoSerifSC-VF.ttf"`、
  `FONT_SIZE=72`、`SUBTITLE_BOTTOM=H-320` 全部硬编码；而
  `app/config/config.yaml:72-80` 有完整 subtitle 段、`config.py:171` 有
  `ProfileSubtitle` 模型——配置了但没人读。
- 且 FONT_PATH 是机器特定绝对路径，换机/换盘即炸（compose 跑到烧字幕才抛）。
- 建议：compose 改读 `ProfileSubtitle`；FONT_PATH 支持 config 配置 +
  开机自检（compose 入口先 truetype 试载一次，早失败）。

### P1-3 shot_builder 模块级 `warnings.filterwarnings("ignore")`
- 证据：`shot_builder.py:25-26`——import 即全局静默所有警告，污染整个进程
  （包括同进程的 orchestrator、API 服务）。没有局部性。
- 建议：删掉。若只为压某个第三方库的噪音，用 `warnings.catch_warnings()`
  局部包。

### P1-4 compose 拼旁白不校验各 wav 采样率一致
- 证据：`compose.py:611-621`——`sr` 在循环里被最后一个文件的采样率覆盖，
  chunks 直接 `np.concatenate`。现在靠 voice.py `_mp3_to_wav` 统一转 16k 的
  **约定**不出事，但没有 assert。一旦某帧音频来自别的来源（比如手动补录），
  采样率混入会静默变速/变调。
- 建议：循环里加 `assert sr == 16000`（或与首帧一致），失败即抛。

### P1-5 核心服务测试覆盖缺口
- 证据：cosyvoice.py(626行)、voice.py、compose.py、motion.py、upscale.py、
  bgm.py、polyphone.py 全部零直接测试；voice 仅 test_tts_fingerprint 4 断言。
  92 用例集中在编排/切分/分镜/生图/台账。
- 另：`test_compose_first_production.py:33,41`、`test_production_regressions.py:36-42`
  直接 subprocess 调 ffmpeg，无 `shutil.which` 守卫——无 ffmpeg 的机器上是 fail
  而非 skip。
- 建议：至少给 polyphone（纯函数，最好测）、timing_assert（已是纯逻辑）、
  voice 的指纹/manifest 逻辑补单测；ffmpeg 依赖用
  `pytest.mark.skipif(not shutil.which("ffmpeg"))` 守。

### P1-6 config.py 的 .env 三套加载并存
- 证据：`config.py:313` pydantic `SettingsConfigDict(env_file=...)` +
  `:30` 手写 `load_env()` + `:366-384` `Settings.load()` 显式传 kwargs——三套。
  pydantic 自动读 env 形同虚设。
- 建议：收敛成一套（手写 load_env + 显式 kwargs），删掉 pydantic env_file。

### P1-7 shot_builder 时长回退 `or 3000` 静默捏造
- 证据：`shot_builder.py:226` `a_dur = f.audio_duration_ms or 3000`——audio 时长
  缺失时静默按 3s 算。虽然 compose 会按真实音频重算，但装配出的 shots 元数据
  本身是假的，verify 前的任何消费方都会被误导。
- 建议：audio 缺失时直接报错（先跑 TTS），至少打 warning。
