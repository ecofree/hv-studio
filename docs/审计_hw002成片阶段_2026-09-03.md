## 一、第三方面审结论逐条复核

### P0-1 字幕孤行标点 + 折行断词 —— ✅ 属实（实测复现）

用 compose 实际 `_wrap()` 跑真实文案：

```
[是一个手持磨秃汉节的人，] → ['是一个手持磨秃汉节的人', '，']    # 逗号孤行
[向群臣抛出一道诏令：招募勇士，] → ['向群臣抛出一道诏令：招', '募勇士，']  # 拆词
```

- 根因：`compose.py:_wrap()` 纯按像素宽度逐字截断，无避头尾法则（禁行首标点）、无词边界保护（把"招募"拆两行）。
- **补充发现（报告未提）**：`_wrap` 用 `draw.textbbox` 逐字累积测量，本身也对（非等宽的中文尚可），但**未对行首禁则（，。、；：等）做回退**，也未对**行尾强制带走紧跟标点**（中文里"人，"应同行）。是同一个函数的一处缺陷，修复时应同时解决"孤行"与"拆词"。

### P0-2 极短镜头违背 1.6s 下限 —— ✅ 属实（实测复现）

```
assert_episode_timing(ep) → {'ok': False,
  'fails': ['shot-056: 帧数 31 < 40(1.6s 下限)',
            'shot-085: 帧数 37 < 40(1.6s 下限)']}
```

- `shot-056` "归途上，" audio=1152ms + head100 + tail0 = **1252ms / 31帧**
- `shot-085` "在此之后，" audio=1392ms + head100 + tail0 = **1492ms / 37帧**
- 根因：`script.py` 剧本里这类**逗号断开的短从句被写成独立短行**，`split_long_sentence` 只对 **>18 字**的长句切分，对本来就独立的短行不做合并保护。
- **根因更深一层（报告未点破）**：见下「新发现 #A」——m2 直通路径**根本没在渲染前调断言**，这条失败是事后手动跑出来的，正常 `compose.py` 直接出片时**不会自动拦截**。

### P1-1 零 BGM —— ✅ 属实（ffprobe 实测）

- 成片音轨仅 1 条：`aac, 1ch, 114kbps`（单声道纯人声）。
- **补充（报告未点破）**：`config.yaml` 的 `profile.bgm: {volume: 0.18, fade_out_sec: 5}` **配置早已预留**，但 `compose.py` 的 ffmpeg 命令**从未拼接 BGM 轨道**——属「配置设计了、代码没接线」。修的时候不是"想方案"而是"把预留接上 + 找 BGM 素材"。

### P1-2 字幕基线下沉 + 字体回归 —— ✅ 属实

- `compose.py` `BASELINE_Y = H - 430`（实码），`FONT_PATH = msyhbd.ttc`（微软雅黑粗，硬编码）。
- `config.yaml` `subtitle.font: 思源宋体`、`margin_bottom: 320`（→ Y≈1600）**从未被 compose 读取**。
- 结论：compose 对字幕**完全没用 config 的字幕配置**，是另一处「配置-代码脱节」。

### P1-3 关键词大字花字未实装 —— ✅ 属实

- `app/services/subtitle.py` 整文件是 **STUB**：`render_ass()` / `burn_in()` 均 `raise NotImplementedError`。
- `config.yaml` `subtitle.keyword`（亮青 80px 花字）**设计了但从未接线**，5 分钟纯白字无节奏。

### P2 字体每帧重载 —— ✅ 属实

- `_draw_subtitle()` 内 `_load_font(FONT_SIZE)` 每次调用都 `ImageFont.truetype`，7,475 帧 = 7,475 次加载。应在模块级缓存。

### 四、角色一致性脱钩 —— ✅ 属实（且比报告更严重）

- 实测：hw-002 的 **face_sim 0/93 非空、ref_pack_id 0/93、shot.stage 全空**。
- `ImageEditRequest`（参考图 edits 收脸）**能力可用**（hw-001 pipeline 用过），`m2_scenes.py` 却只 `get_image().generate()` 纯文生图，24 张底图零参考约束。
- `ZHANGQIAN_ANCHOR` 文字锚定存在，但只约束"穿什么"，不约束"长什么样"。

## 二、独立自查发现（第三方报告未覆盖 / 诊断不完整）

### 🔴 新发现 #A：存在"两套割裂渲染路径"，这是上述多数问题的总根因

这是本次审计最重要的结构性发现，报告把问题列成了零散的 8 条，实际大多是**同一个架构分裂**的症状：

| | 路径 A：pipeline 编排器 | 路径 B：m2 直通（本次实际使用） |
|---|---|---|
| 入口 | `app/managers/pipeline.py:run_episode` | `bin/m2_scenes.py` + `bin/m2_shots.py` + `python -m app.services.compose` |
| 角色一致性 | ✅ edits 注入 + face_sim 门控 | ❌ 纯文生图 |
| 渲染前断言 | ✅ 合成后 `assert_timing_or_raise` | ❌ **从不调用**（本次失败是手动跑的） |
| 超分 | 走统一 upscale | 走统一 upscale（同源） |
| 配置读取 | 读 config | ❌ **硬编码默认值，完全不读 config** |

**证据**：`compose_and_verify()`（pipeline 里）合成后会用 ffprobe 回填视频帧数并跑断言 #5；而 `compose.py` 直接 `__main__` 入口只 `compose_episode()` 就跑完退出，**断言形同虚设**。

**推论**：报告 P0-2"渲染前未前置阻塞"、第四节"角色一致性脱钩"、以及大量配置失效，**共同指向同一个病**——m2 阶段为了快速出片新写了直通脚本，绕过了 `config.yaml + pipeline.py` 的规范中心，造成**第二套硬编码默认值**与配置漂移。若只修单个症状，下次新脚本还会复发。

### 🟠 新发现 #B：motion 配置大规模失效（含 max_zoom 越界）

报告未审计 `motion` 维度。实测三处脱节：
1. `ZOOM_LADDER = [1.12, 1.26, 1.40, ...]` —— **最大 1.40，超过配置 `motion.max_zoom: 1.15`**。1.40 裁切窗 ≈ 771×1371，放大到 1080×1920 需 1.4 倍插值，**锐度损失明显**（超出"有损下采样"安全线）。
2. `motion.forbid_consecutive_same: true`（禁相邻镜头同向运镜）**配置存在但从未被读取**——m2_shots 靠手写 `MOTION_CYCLE` 全局轮换近似，实测仍有 **8/92 对相邻镜头同向**。
3. `config.rhythm.min_shot_ms: 1600 / max_shot_ms: 6000` 与断言阈值 40/200 帧**口径未打通**（配置单位 ms，断言单位帧，中间隔了 FPS，靠人肉对齐易漂移）。

### 🟠 新发现 #C：超分引擎 = PIL Lanczos，非配置声明的 RealESRGAN

- `upscale.py` `ENGINE = "pil_lanczos"`（M1），config 却声明 `postprocess_upscale.engine: realesrgan / scale:2 / device:cuda / tile:512`。
- 即：**配置期望 GPU RealESRGAN 超分，实际跑的是 CPU 双线性放大**。画质上限被锁死在 Lanczos 插值，5 分钟放大画面不会有真超分细节。
- 报告未提（它聚焦字幕/音频，未审 upscale 层）。

### 🟠 新发现 #D：compose 视频编码参数与 config 声明不符

- `compose.py` 硬编码 `libx264 / medium / crf18 / -threads 2`。
- config `compose:` 声明 `h264_nvenc / preset p4 / cq20`（GPU 硬编）。虽 fallback 到 libx264，但**连 crf 都不同（18 vs 20）**。
- 次要，但反映 m2 直通对 config 全面失读。

### 🟡 新发现 #E：compose 时长口径与断言口径不一致（93 镜中 69 镜）

- compose 渲染时对**单源句首镜**加 `head=100`（`_group_of` 变化），**句尾镜**加 `tail=150`；而 `m2_shots` 写入 shot 的 `duration_ms = audio+350`（固定 350，不区分首/中/尾）。
- 实测 **69/93 镜 `shot.duration_ms` ≠ compose 实际渲染时长** → 断言基于存的 `duration_ms` 判，渲染按另一套算，**两者会漂移**。当前恰好短镜两套都失败（碰巧一致），但**不能保证长期成立**——这正是 #A 双轨的又一恶果。

### 🟡 新发现 #F：字幕逐字常出现但文档样例之外还有孤行概率

我抽查了若干帧，除报告给的两例外，诸如 `条枝眩人。`（单行OK）、较长句拆行仍可能产生孤标点。属 #P0-1 同源，修复避头尾后整体消失，非独立问题，仅提示"不止两个 case，是系统性缺陷"。

## 四、建议修复顺序（先总根因，再单点）

**第一步（架构收敛）**：把 m2 直通脚本**收敛回 pipeline** 或**为 compose 直接入口补上前置 gate**——
- `compose_episode()` 顶部调用 `assert_timing_or_raise(ep)`（短镜、超长镜、音频对齐统一前置拦截）；
- m2_scenes 生成底图后，复用 `pipeline.stage_image` 的 edits 收脸路径（先为张骞建一张定妆锚图做 ref）；
- 这是**一次性**投资，能让后续所有修复都落在同一套 gate 上，避免再漂移。

**第二步（字幕排版，纯本地零成本，优先级最高）**：
- `_wrap()` 加避头尾（行首禁 `，。、；：…`，行尾优先带走紧跟标点）+ 中文最小不可断（至少 2 字）保护；
- 标题字对 TTS 停顿无益、对排版有害 → 渲染前 `rstrip` 句末标点（对"抖音竖屏大字解说"是行业惯例，报告建议采纳）；
- `BASELINE_Y` → `H - 430` 调到约 `H - 320` 附近（约 Y1550-1600，避开人物核心 + 下方留 320px）；
- `_load_font` 提到模块级缓存一次；字体切回思源宋体（若本机无则先确认字体文件存在，避免 `ImageFont.truetype` 抛异常）。

**第三步（BGM，需素材）**：compose 拼入一条 BGM 轨道，音量 ~0.15-0.18，首尾 3-5s 淡入淡出；`config.bgm` 已有字段直接对接。需要先准备一段合适的古风/史诗 BGM 文件。

**第四步（短镜合并）**：`script.py` 增加"短从句并入后句"——切分后若某 frame 预估时长 <1.6s 且非句末，与后一 frame 合并；或在剧本层就不把逗号短行独立成段（治本：改写剧本 2 处）。

**第五步（配置对齐，收尾）**：m2_shots 读 `motion.max_zoom/forbid_consecutive_same` 替代硬编码 ZOOM_LADDER 的 1.40 越界；upscale 按需切 RealESRGAN；compose 编码参数读 config。
