## 前置事实（均已代码核准，非推测）

### 1. 孤儿 wav 精确盘点
判据 = 盘上 `*.wav` 中，既不被 `episode.json` 任一 `frame.audio_path` 引用，也不被
`_tts_manifest.json` 键引用的文件。分集结果：

| 集 | 盘wav | frames引用 | manifest引用 | 孤儿 | 体积 | 子帧格式 |
|---|---|---|---|---|---|---|
| laogongtuan | 436 | 365 | 365 | **71** | 7.3MB | 65 |
| hanwu-ch3 | 130 | 101 | 0 | **29** | 2.7MB | 29 |
| hanwu-feature | 54 | 53 | 0 | **1** | 0.2MB | 1 |
| hw-002 | 94 | 88 | 0 | **6** | 0.6MB | 6 |
| hanwu-prologue | 9 | 9 | 9 | 0 | 0 | 0 |
| hw-001 | 6 | 6 | 0 | 0 | 0 | 0 |
| **合计** | | | | **107** | **~10.8MB** | 101 |

- 孤儿全部是 **`frame-NNN-NN.wav` 子帧格式**（旧切分版本把长句切成 `frame-NNN-01/02/03`
  子帧）；新切分用独立 base frame id，子帧形式已废弃。
- manifest 引用数为 0 处 = ch3/feature/hw-002/hw-001（旧目录无 manifest 基线），但它们的
  frames 引用与孤儿互斥，判定仍是安全的。
- **删除不会破坏任何当前引用** —— 三重判据（frames + manifest + 子帧废弃格式）同时命中。

### 2. 两个根目录脚本的本质
- `rebuild_laogongtuan_plan.py`：核心是**硬编码的 60 段"文本锚→LGT 图"映射表（SCENES）
  + 跨集复用表**。这是**人工创意/编辑分镜单**，不是可泛化逻辑 —— 通用编排器不可能知道
  "每部片哪句台词配哪张图"。**不可收进 orchestrator**，应保留为"这一集的人工资产"。
- `batch_generate_lgt.py`：独特逻辑 = 读 `image_prompts.json` → 拼 prompt
  （`en + style_suffix + negative`）→ 落盘 `shots/{LGT}.png` → 幂等跳过。
  **这正是新 `stage_images` 做的事**，但 prompt 拼接细节需对齐（见下）。

## 方案

### A. 孤儿 wav：加一个 opt-in 维护命令（低风险，推荐执行）
不自动清（避免误删交付集），提供一个显式维护子命令，先 dry-run 列出、`--apply` 才删：

```
hv episode <id> audit-wav --dry-run   # 列出孤儿（默认）
hv episode <id> audit-wav --apply     # 删孤儿（只删三重判据命中的）
hv episode <id> audit-wav --apply --all   # 扫全部集
```

安全设计：
- 判据硬编码为 frames ∪ manifest 都未引用，且文件名匹配子帧/孤立 id 模式。
- 默认 dry-run 只打印不删（符合个人"只读审计，先观察后动手"的纪律）。
- 删除走 `os.remove`（小批量、每集逐个），不做 `rm -rf`。
- 交付集 laogongtuan/prologue 有 manifest 作第二道保险；无 manifest 的集靠 frames 引用。

理由：107 个文件仅 ~10.8MB，价值是**清障**（避免旧 wav 干扰未来 `--force` 全量重合成时
的 manifest 基线）与**盘面整洁**，不是省空间。风险极低但仍有，故 opt-in。

### B. `batch_generate_lgt.py` → 薄封装对齐 `stage_images`（推荐）
保留脚本名（避免破坏肌肉记忆/文档），但内部改为调用 orchestrator 的 `stage_images`
或与它共享同一个 prompt 构建函数，消除双份逻辑漂移。

需做的对齐：
1. `stage_images` 已修正为**扁平 ImageConfig**（`im.engine='gpt-image-2'`、`im.size`、
   `im.quality`），不再用不存在的 `im.primary.*`（这是刚发现的真实 bug，已修）。
2. 确认 `stage_images` 的 prompt 拼接 == `batch` 的 `full_prompt`
   （`en, style_suffix. negative`），输出路径都落 `shots/{LGT}.png`、幂等跳过。
3. batch 变薄封装：`python batch_generate_lgt.py <集id>` → 内部调 `stage_images`。

好处：生图 prompt 逻辑只维护一处（stage_images），batch 只是 CLI 入口别名，不再有
"改一处漏另一处"的漂移。

### C. `rebuild_laogongtuan_plan.py`：保持为人工资产，不做自动化（明确不做）
- 它承载的是**这一集的分镜决策**（文本锚→图、grade、跨集复用），天然不可泛化。
- 建议做法：把它从"根目录一次性脚本"**归位为集目录内的人工计划单**
  （`episodes/laogongtuan/scene_plan.gen.py` 或移入 `docs/`），并加文件头注释说明
  "这是 laogongtuan 的人工分镜单，不要删；其他新集需另行人工编写 scene_plan.json，
  不适用此脚本"。若未来要建"通用分镜助手"，那是独立 feature（可用 LGT 历史作样例训练），
  不在此次范围。

## 结论（一句话）
- **孤儿 wav**：107 个 / ~10.8MB 纯残留，加 `audit-wav` opt-in 命令，dry-run 默认、apply 才删。
- **batch 脚本**：薄封装对齐 `stage_images`，prompt 单源，消除漂移。
- **rebuild plan 脚本**：保留为人工分镜资产并归位注释，不自动化。
