# 高质量历史视频流程与 Writing-DNA 审计

审计日期：2026-10-18。项目：`D:\hv`。文案基础：`resource/风趣历史.writing-DNA`。

## 结论

项目已有较扎实的**素材保护、音频对齐、字幕几何、缓存、预算和候选片证据**能力；最近的 84 秒样片也证明首帧设计、局部环境动画、受限分层视差可以保留现有画风和人物。

但距离稳定生产高质量历史视频，主要缺口仍在上游：**史料如何变成可信的主张，主张如何变成好讲的故事，故事如何无损进入声音与画面**。现有流程能检查“输出是否忠实于选中的源稿”，不能判断“选中的源稿是否准确、好听、值得看”。已经抽查到原典语境、角色和死亡方式被改写的实例，不能靠增加动画补救。

Writing-DNA 应保留其市井表达、具体利害、场景感和情感转折；需要优先纠正的是证据约束互相打架、范例未经核验、语料污染、稿件与 TTS 多版本分叉，以及把一种宫廷悲剧套路当作所有历史题材的通用答案。

**建议顺序：先校准事实与唯一正文 → 修通文案/导演/声音交接 → 建立逐幕叙事设计 → 扩展整集动画 → 用实际听看和观众反馈验证。** 不建议先换画风、换旁白音色或批量重生成素材。

## 主要发现与修复建议

### F01 · P1：关键史实与引文已经发生失真

**事实。** 三处高影响抽样均有需要修订的内容。它们也出现在 `episodes/xlc-01/script_narration.md` 的实际生产源中，不只是旧范例。

1. **托孤开场**：两臣受顾命有据；“佳儿佳妇”在《通鉴》卷199的具体语境是永徽六年褚遂良追述先帝之言。原稿将它写成“生平最后一句话”，再加太子手交入两臣掌心、李治当场视其为枷锁。受检文献不能支持这些确定性现场细节。同段褚遂良官职亦需按时点纠正，不能把后来任官倒置到临终场景。[《旧唐书》卷80](https://zh.wikisource.org/wiki/舊唐書/卷80)、[《通鉴》卷199](https://zh.wikisource.org/wiki/資治通鑑/卷199)
2. **李恪之死**：原稿第67–79行把求情写成高宗与长孙无忌的直接对话，并呈现“当天下午”“血溅市曹”“斩杀”。受检《通鉴》永徽四年条记高宗向侍臣求免，反对者为崔敦礼；又区分房遗爱等斩刑与李恪等赐自尽。这是关键角色和处刑方式发生改变。[《通鉴》卷199](https://zh.wikisource.org/wiki/資治通鑑/卷199)
3. **幼女死亡引文**：原稿第126–127行将一句改写文字同时归给《旧唐书》《唐会要》，并称两书“唯有”克制记录。《唐会要》原文措辞不同；《旧唐书》相关传记未叙死因，但卷6史评存在另一种指控，不能用一段未记载推成整部书都没有。此事仍应保留史籍差异与死因未可确证的边界。[《唐会要》卷3](https://zh.wikisource.org/zh-hant/唐會要_(四庫全書本)/卷003)、[《旧唐书》卷6](https://zh.wikisource.org/wiki/舊唐書/卷6)

**影响。** 叙事越逼真、声音越有情绪、画面越有现场感，错误越容易被当成确定事实。当前字幕忠实于源稿，并不能阻止源稿中的失真。

**修复。** 建立轻量 `claims.json`：句段 ID、主张、来源/卷页/原文、证据类型、反证、允许的表达强度、画面限制、复核状态。优先覆盖引号对白、数字/疆域、死亡方式、官职时点、争议动机。来源之间有转抄关系时不要把它们算作多个独立证据。

**验收。** 所有关键主张可回到具体出处；改写不用原文引号；争议口播与画面保持一致；不能一边说“死因未明”，一边直接画行凶。上述三处只是抽样，不能推算全片错误率。详见 [原典核查报告](/D:/hv/state/audits/history-content-20261018/claim-checks.md)。

### F02 · P1：DNA 的硬规则在相互抵消

**事实。** 主文档第78行强制生死场面加入生理动作，第217–219行又禁止脑补心理对白。正向范例第65–71行仍直接替李渊断言内心算计；认知框架第32行把诗词“一律”当作证明心理动机的物证。第三集第174–195行先写“时人以为”，再扩大为当夜几乎所有官吏百姓一致认定，并把不确定死因改写为确定的精神绞杀。

**影响。** 模型同时收到“不能虚构”和“必须写出未必有记载的细节”，容易优先满足更具体、更有戏剧性的指令。样例比抽象禁令更容易决定最终文风。

**修复。** 规则顺序改为：**证据边界 > 清楚好懂 > 具体场景 > 幽默与修辞**。现场动作只能来自有出处的记载，或明确放入“示意性重建”视觉层；不能为了生动把新动作添入口播事实。诗文先核作者、作年、对象和文体，作为解释线索而非直接心理测量。写稿阶段必须继承主张 ID 和争议限制，不能只给“物理动作大纲”而丢掉证据。

**验收。** 重写至少三组带出处的正反范例：可信场景、适度幽默、争议表达。范例与硬规则不再冲突；说书人改写后再做一次事实/引号回查。

### F03 · P1：语料库不是当前宣称的“103 篇纯净、逐篇分析的历史长文”

**事实。** 文件数确为103，raw 与 meta 一一对应，也保留了原文链接，这是可利用的基础。但：

- 至少两份是公众号推广文，如《每日必读的几个优秀微信公众号》《2018年火爆朋友圈的公众号…》。
- 2 份 raw 残留 `document`/`window` 等网页脚本；33 份命中页尾或页面操作语句，需逐项清理，命中数不等于33篇完全不能用。
- 《被偷走的一百年》两版正文相似度约99.67%，差异主要是抓取页尾；另一组同题《活佛升天》混有排版与网页脚本差异。不能把103个文件直接视作103份独立历史样本。
- 103 份 metadata 的 `topic_tags`、`source_types`、`structure_pattern`、`notable` 各只有一种值。推广文也被标成正史解构/档案诗文互证，标签不能证明逐篇分析。
- 当前 raw 全字符数315,710、汉字数251,227；meta 的 word_count 合计315,710。文档“296,213字”没有可复算口径，不能继续以精确数字宣称全量统计。

**修复。** 原始 raw 不删除；新增可重建的 curated 清单，标记正文范围、污染、近重复组、非历史/广告、实际题材、可学的语言技巧及不应继承的表达。保留来源链接/抓取时间/内容哈希，并记录可复用范围。语料用于学习叙事技巧，不能作为史实证据；不需要把103篇全部塞进提示词。

**验收。** 精选样本无广告/脚本/页尾残留；同篇多抓取只占一个权重；每个标签能指向文中证据；字数统计有脚本、明确正文口径和排除清单。详见 [语料质量证据](/D:/hv/state/audits/history-content-20261018/corpus-quality.json)。

### F04 · P1：正文、TTS 专版与生产源是多套可独立漂移的文本

**事实。** 第一集 TTS 版在废后段把“右仆射”改成“右仆夜”、把“李勣”改成“李绩”，并改写引语；第七集还删改了实质叙事，不能仅看文件名就认为是同一正文。其他部分差异只是删除画面提示，不能笼统算成漏句。当前 `xlc-01` 生产源中的这些同音字已恢复，**本审计不宣称当前成片仍把李勣字幕写错**；问题在于范例库依旧保留可再次导入的分叉。

`spoken_text.compile_text` 只改标点并保护字面内容，这是正确边界。但它保护的是已经选中的源稿，不能发现源稿在导入前被人工或另一个脚本改过。

**修复。** 固定唯一经过确认的口播正文，TTS 文本由适配器派生，绑定原文版本和字符映射。专名读音保存为独立词典/能力受控的发音参数，不能把错误字形重新送回字幕。内容删改必须变成可阅读 diff 和新版本；外部音频附生产文本哈希与录制/生成清单。

**验收。** 发布源、旁白文本、字幕都能回到同一批准正文；任何非标点变化显式列出；不把 legacy 多音字替换移植到 v2。详见 [原稿与 TTS 差异](/D:/hv/state/audits/history-content-20261018/script-tts-diffs.json)。

### F05 · P1：导演意图在格式转换中丢失，某些提示还会混入口播

**可复现事实。** 隔离调用现有纯函数得到四种结果：

| 输入 | 当前结果 |
|---|---|
| `[语气：低沉][音效：雷声]` 经 setup 工具 | 白名单清洗删除，后续计划不能知道这些要求存在 |
| `[pause=0.5s]` 直接进 v2 parser | 作为正文保留，未识别成停顿 |
| 同一英文停顿经 setup | 直接删除，停顿意图丢失 |
| 跨行 `【画面：…】` 或较长的“语音压低10%…混响”括注 | 未完整识别为导演说明，可被算作旁白，未产生 review_required |

实际第八集有跨行蒙太奇提示，第二集有混合“指令+吐槽”的长括注；这些不是只在虚构测试输入里才可能出现。现有 TTS 专版人工去掉部分提示，因此**不能推定当前片子已经读出了全部导演说明**。现有第一集存储计划却确实为0 cue；原始导演稿解析可提取48个 cue，说明两份资产的交接缺少可追踪记录。

**修复。** 把正文、表演、声音、视觉分别作为显式字段，统一中文/英文停顿输入格式；每条 cue 必须是已编译、明确不支持待处置、或人工接受现状，不能静默消失。导入先预览差异、排除区与 cue 去向，再原子写入；保留旧源和全部原始 take。

**验收。** 本报告四个反例都能保留正文并追踪意图；真实第二/八集格式通过导入预检；未知指令阻断导入或形成显式待处置项。仅对受影响 parser/import/delivery 组件做隔离测试，再按项目要求执行 production 验收。详见 [导入反例](/D:/hv/state/audits/history-content-20261018/import-probes.json)。

### F06 · P2：文风模板过于固定，正在把“风趣”推成持续沉重的宫廷定罪

**编辑判断，有文本依据。** 第一集从“沉郁厚重、威权窒息”出发，反复要求“冰冷透骨”“字字如刀”；认知框架先给出“必然失衡”“王朝注定灭亡”，再要求避免单因论和宿命论。第二集有口语活力，但疾病、生理动作、商业隐喻和审判式结论仍承担了过多解释功能。

“前80%笑/后20%哭”“第四幕比喻清零”“70/20/10语温”没有本项目观看数据支撑，也和“废除机械比例”冲突；语言DNA推荐三连铺陈，主规范又禁止机械三排比。强制三部曲/八集不能替代选题判断。词库禁掉“不是…而是…”也不能自动改善观点、证据或节奏。

**修复。** 保留亲切说书口吻，但按选题选择悬疑调查、人物抉择、制度解释、旅行见闻、战争地理等结构。每集先写一句核心问题、观众能带走的一个认识；每幕写“新证据→人物选择→后果→下一个问题”。分析模型只作可被反证的假设；笑点来自情境，不强迫贬损人物。允许欣喜、好奇、惊讶、克制、遗憾等不同结尾。

**验收。** 不看标题也能分辨各集的核心问题和信息增量；每幕都推进答案；没有为满足比例硬插笑话/升华；找不熟悉该段历史的试看片者复述因果，记录其卡住的位置。词频只提示复读，不作好文案分数。

### F07 · P2：现有视觉指南不适合作为本项目的视频制作规范

**事实。** `视觉风格指南.md` 主要是公众号单句段、图前引线、图后补刀，并要求30%证据图、40%影视/表情包、30%场景。安装的 Skill 却把它描述为含“动态沙盘…音画同步规范”，实际文件没有这些具体规范。影视截图/梗图占比规则也与本项目固定 house look 不一致。

**修复。** 把文章排版规范降为可选渠道附录，新增视频制作章节，但**画风仍以 profile.image.style_suffix/negative_clause 为唯一权威**。建立：角色ID与年龄阶段、时地表、服饰器物参考、镜头目的、视线/位置连续性、画面证据等级、字幕/标题位置、动画层和保护区域。地图边界需绑定时间与依据，不用无说明的现代大面积色块冒充实际控制区。

**验收。** 每个新增镜头都能回答“它帮助理解哪件事”；人物/时期/器物可核；示意、推论和实物证据可区分。保留现有原画，无依据的现场动作不因为已画好就取得事实地位。

### F08 · P2：局部动画已可用，但尚未解决整集的解释性画面不足

**事实。** `production_timeline.py:83` 已能加载剧集 directing.json；`directing.py` 已能编译 visual_events、cards、sound、animation。当前整集没有该配置，84秒样片通过独立设计文件接入同一个 v2 渲染器。`scene_animation` 只有局部可见背景视差、雨和光，既不补画遮挡后背景，也不改变人物动作。

**影响。** 环境动效改善静态感，但不会自动解释顾命关系、官职变化、战争路线或制度利益。抽帧显示画风稳定，暗色室内和人物场景较多；这种气氛是否适合全片，需要正常速度/手机屏幕看审，不能凭接触表断言全片过暗。

**修复。** 先完成每幕视觉设计，再决定哪些镜头需要动：关系建立用人物位置/称谓/连线；选择变化用信息显隐；路线用有出处的地图；争议用并列史料卡；情绪场面使用现有低强度环境动效和停住。对约40秒同图段优先检查信息是否变化，而非强行规定每几秒切镜。

**验收。** 全片有逐镜 purpose、声学锚点、动静曲线与角色保护；普通 produce 可读取同一份设计；换稿会失效；每幕完整看审之后再扩展。不得把 v2 长镜头设计直接判为违反 legacy 的200帧上限。

### F09 · P2：声音“情绪控制”目前主要是后期增益，不是新的表演能力

**事实。** `sound_design.py` 明确只做原样本增益和三种程序氛围，不改音高/时长；本地 Qwen clone 脚本明确拒绝 instruct 情绪指令。通用 delivery 只有能力标记 supported 时才把合适的前置语气 cue 编入请求。这些诚实边界应该保留。

**修复。** 设计表演表而非堆形容词：谁在说、说给谁、这一句希望观众理解什么、重词、速度趋势、停顿、强度范围。先在现有声音上做选 take、短段编辑、停顿、背景声退让；如需新增表演，先验证**同一音色**可用控制，另行固定调用预算并保留原录音。不能用换预设说话人来宣称解决情绪。

增加声场层：雨声可帮助建立空间，衣袖/门声只在有动作依据时使用，关键结论前允许静默；程序和弦不等于完整配乐设计。记录响度、真峰值、跨段音色/噪声/尾音连续性，按目标渠道和实际手机试听确定目标，不在没有平台依据时硬套数值。

**验收。** 原声音色可辨、句意清楚、停顿有目的、声效不抢叙述；同音色 A/B 盲听说明改善在哪一句，不能以指令已发送或峰值未超限代替情绪通过。

### F10 · P1/P2：前置内容审核和音频生成工具没有统一入口

**事实。** 批处理有 `production_admission.check` 和输入批准；直接 CLI produce 调用 run 的路径未见同样的前置检查。最终 publish 仍要求绑定成片与母带的人工批准，这道门存在，不应说项目无审核。

DNA/scripts 下仍有 Gemini、百炼直调脚本，直接 urllib 请求并重试，未接 v2 的持久预算/收据机制。它们不是 legacy-preview 的付费路径；其存在说明项目约定“付费只走v2”还不能靠资源目录的独立脚本自动保障。当前审计未执行这些脚本，也未核实远程模型是否可用。

**修复。** 对预览和正式生产明确区分。正式花费前要求同一份已确认正文和分镜输入；资源目录保留旧脚本供追溯，正式入口改为调用受预算/音色/收据约束的适配器，不能继续由写作工具自行改正文并发起生成。对未支持的声音控制显式失败。

**验收。** 正式入口缺少当前输入核对记录时先报告差异；缓存复用不产生调用；失败/重试/未知结果计入同一预算；不能靠改脚本名字或从另一个目录执行绕开约定。试验不伪造批准。

### F11 · P2：规范版本、旧研究报告和“标杆稿”缺少可信等级

**事实。** master/结构/认知为4.5，语言为4.0，视觉仍是文章规范。TTS 分块有450–650字与600–850字两个口径；第一集宣称8块，实际有9个 text 块。既有竞品报告包含粉丝/播放量、统计比例及平台风险结论，但没有可追踪 URL、采样日期和统计方法。本审计不沿用这些数字或封禁断言。

**修复。** 用一个短索引登记有效规范版本和优先级；Skill 只指向它，避免重复维护长规则。把旧研究标记为待复核参考，把未核验剧本标为 draft，不要统称“官方标杆”。时长按当前音色试读测量；TTS块按实际引擎能力和句义边界划分，不承诺固定字数能杜绝漂移。

**验收。** 从 Skill 进入与从仓库进入得到相同规则；全部示范标注来源、适用目的、核验状态；无来源的观众/平台判断明确为假设。

### F12 · P2：技术验收较强，内容效果尚无可验证的闭环

**事实。** 媒体验证检查流、尺寸、时长、帧包数和解码；字幕有字面、几何及持续时间检查。人工看审目前主要是一段 findings 加 approved/rejected。没有找到把每条事实、每幕理解障碍、声音表现、信息密度与观众反馈关联起来的常规产物。

**修复。** 保持技术候选与发布批准分开，增加轻量分项检查：事实和引文、讲述理解、人物连续性、地图与道具、口误及读音、字幕断句、声效抢戏、首帧承诺是否兑现。记录问题时间点与归属工序，不靠总分掩盖一个未解决的关键错误。发布后才用真实留存/评论问题验证假设；现阶段没有数据就用小规模试看片记录，不能预报完播率提升。

**验收。** 当前51项语音疑点逐项试听并留结论；完整长片正常速度看审；事实错误回文案，口误回音频，画面问题回设计。候选通过技术检查后仍明确待人工确认。

## 建议的 Writing-DNA 结构

不必推倒重写，也不必再堆一份更长的提示词。将现有资产分成六个职责清楚的部分：

1. **核心风格**：保留市井口语、具体利害、节制幽默、尊重复杂人物；只保留少量有核验依据的范例。
2. **史料方法**：来源类型、卷页、成书语境、互相依赖、反证、争议、引文原样校验；禁止把分析当档案、把想象当观察。
3. **故事设计**：选题问题、人物目标/阻力/选择/代价、每幕信息增量、结尾兑现；模板提供选择，不预设每个帝王都走同一悲剧弧线。
4. **口播与表演**：唯一正文、专名读音、重词与停顿、真实试读时长、同一声音的能力边界。
5. **视听交接**：scene/beat ID、claim ID、旁白范围、画面目的、可见动作、角色/年代、声音事件、动静设计和可用素材；画风引用全局配置。
6. **范例与语料索引**：raw 原件保留；curated 样本有来源、去重和适用标签；draft/verified 分开；修改记录可追溯。

最小交接单位可以只有一张“叙事片段卡”：

| 字段 | 示例：李恪段 |
|---|---|
| 观众问题 | 高宗是否曾试图免去宗室的死罪？ |
| 证据 | 《通鉴》卷199永徽四年条，绑定具体原文 |
| 允许口播 | “据《通鉴》记载，高宗曾请求免去荆王、吴王的死罪……” |
| 不允许扩写 | 不把反对者换人，不加“当天下午”，不将赐自尽画成市曹斩首 |
| 画面目的 | 分清皇帝、侍臣、受处置宗室的关系和决定过程 |
| 声音目的 | 克制讲清转折，引用与解释有轻微停顿区分 |
| 收束 | 呈现决定的后果，再进入权力关系的分析；不假装看到人物内心 |

## 实施顺序与验收关口

| 批次 | 具体产物 | 完成条件 |
|---|---|---|
| A：可信基线 | 首集关键主张台账、三处事实修订建议、原稿/TTS/生产源差异清单 | 原典/推论/争议可区分；正文版本明确；旧音视频全部保留 |
| B：文案基础整理 | 去重/去污染的 curated 索引、规范冲突表、三组新范例、单一版本索引 | 不再引用污染样本作标杆；范例自身满足史实边界 |
| C：交接修复 | 导入预检、正文映射、cue 去向清单、受控TTS入口 | 四个反例及真实格式案例通过隔离验证；预算/声音保持既有约束 |
| D：逐幕设计 | xlc-01 全片 beat/scene 设计、角色与时地表、关系/地图/引用卡方案、声音表演表 | 每幕都有信息推进；不用雨/推拉替代讲解；画风和声音不换 |
| E：代表片段 | 选择覆盖开场、一次因果解释、一次转折的片段做新旧对比 | 同源比较、完整听看；先检查内容改善，再评动画强度 |
| F：整集交付 | 完整 directing 配置、候选、技术证据、分项听看/事实记录 | source/hash/frame/sample/subtitle 全部有效；51项及新增疑点有处置；人工批准独立存在 |
| G：效果复盘 | 首帧/标题与正文一致性、试看片问题记录、发布后真实反馈 | 用数据和具体反馈修订下一集；不预设固定模板必然爆款 |

A–C 应先于批量生成和整集重渲染；D 可以与文案校核并行设计，必须在正文定版后重新绑定时间轴。旧84秒样片保留作技术对照，其中引用与场景需随最终史实修订一并复核，不能因为已经做过动画就免审。

## 最应保留的东西

保留现有画风与旁白音色，保留 source-preserving v2、外部母带导入、原始 take、图像缓存、声学字幕、预算、候选回执和人工批准边界。现有改造有价值；下一阶段重点应放在**让素材表达准确的历史问题，让每幕提供新的理解，再让动效与声音服务于这一变化**。
