# 单条 15–20 分钟长视频落地方案

> 状态：**方案草案（未改代码）**　适用对象：《汉武大帝：刘彻简史》系列  
> 基于 TECH_DESIGN.md（M0–M5 路线）+ hw-001 实测数据（21s / 76字 / 6 镜头）+ CosyVoice v3.5-flash 已通  
> 目标形态：**单条 15–20 分钟成片，发平台**；画面策略：**场景复用 + 关键镜头新图**

---

## 1. 一句话结论

**直接拿现有 4 分钟管线放大 5 倍是一条死路**（约 310 镜头 / 310 张独立古风图 / ¥300+ 生图费 / 静态图撑满 20 分钟会审美崩塌）。

可行的路径是：**从『逐镜头一张新图』切换到『场景资产复用 + 高光镜头新图』的图层化叙事模型**，把画面压力从「310 张独立图」收敛到「≈70 个场景资产 + ≈60 张关键新图」，同时把单集时长上限从架构层放开，把脚本拆成多个可独立事实校验的「幕」(act)。

> 一句话：**画面成本的关键不在镜头数，而在『唯一场景数』。** 长视频能不能落地，取决于能否把镜头归并到可复用的场景资产上。

## 2. 体量硬测算（实测比例外推）

hw-001 实测语速 **≈ 217 字/分钟**（76 字 → 21.0s）。据此推算：

| 目标     | 旁白字数      | 镜头数(每镜~14字) | 逐镜新图    | **场景归并后唯一图**              |
| ------ | --------- | ----------- | ------- | ------------------------- |
| 15 min | ≈ 3,260 字 | ≈ 233       | ≈ 233 张 | **≈ 60–70 场景 + ~50 关键新图** |
| 20 min | ≈ 4,340 字 | ≈ 310       | ≈ 310 张 | **≈ 70–80 场景 + ~60 关键新图** |

**成本（单条，估算）：**

| 项目                       | 单价                       | 20min 估算                            | 说明            |
| ------------------------ | ------------------------ | ----------------------------------- | ------------- |
| CosyVoice v3.5-flash TTS | ¥0.8/万字符                 | **≈ ¥0.35**                         | 可忽略（已通）       |
| 场景资产图（复用）                | 一次性                      | 每场景 ¥1(high) ≈ ¥70–80 首建            | 后续集复用，边际 ¥0   |
| 关键镜头新图（edits）            | low ¥0.043 / high ~¥1.25 | 60 张 × (low迭代+high成片) ≈ **¥80–100** | 含 1–2 轮重制     |
| Ken Burns / 超分 / 合成      | 本地                       | ≈ ¥0（电费）                            | RTX 2060 12GB |
| I2V（可选，8–15 高光）          | 本地 Wan                   | ≈ ¥0                                | 路线 A+，非必须     |

> **画面策略收益**：逐镜 310 张 high ≈ ¥310–390 → 场景复用模型 ≈ ¥150–180（含首建资产 + 新图）。**降 55–60%**，且镜头更长更稳。

**叙事时长预算：**

- 旁白按 ~200–220 字/分，20min ≈ 4,200–4,600 字
- 建议结构：**开篇钩子(~40s) + 3–4 幕(每幕 4–6min) + 收束/总结(~60s)**
- 每幕 = 一个可独立生成、独立史实校验、独立资产集合的单元

## 4. 架构升级：从『逐镜出图』到『场景资产 + 幕』

### 4.1 核心新概念：`scene`（场景资产）与 `beat`（叙事节拍）

引入两级结构，介于 `shot` 之上、episode 之下：

```
episode（单条 15-20min 长片）
├── act 01 《初登大宝》  ── 事实闸门独立单元
│   ├── beat 0101        （叙事节拍：即位 / 朝会 / 隐忍……）
│   │   ├── shot …        现有层级，负责画面/运镜/字幕
│   │   └── …
├── act 02 《剑指匈奴》
└── …
```

- **scene 资产**：跨 beat/shot 复用的画面底本（宫殿、草原、朝堂、长城……），只做一次，用 edits 注入多组 prompt 派生「同一场景不同光线/机位/人物」，**不重复生图付费**。
- **scene 复用 ≠ 画面重复**：靠 3 个派生维度打破单调——
  1. **机位/裁切**（同资产推近/拉远/pan）
  2. **光线/时节**（晨/暮/雪/月）
  3. **叠加层与人物**（粒子、前景元素、角色在场景中站位）

### 4.2 关键改造点（指到具体文件）

| 改造                   | 现状文件                            | 需要新增/修改                                                       |
| -------------------- | ------------------------------- | ------------------------------------------------------------- |
| scene 资产注册表          | 无                               | 新增 `config/scenes.yaml`（scene_id → 底图/参考包/prompt 模板/复用规则）     |
| Episode schema 加 act | `app/models/*.py`               | act 层级：act_id/title/beats/shots 归属；scene_id 字段进 shot          |
| 场景归并生成器              | 无                               | 新 `app/services/scene.py`：按 scene_id 派生（机位/光线/前景），缓存 scene 底图 |
| 幕级编排器                | `app/managers/pipeline.py`      | run 单位从 shot → beat/act；断点续跑按 act                             |
| 长片 compose           | `app/services/compose.py`       | 支持 act 分段拼接 + 超长参数校验；大图集释放内存                                  |
| 长片时序断言               | `app/services/timing_assert.py` | 断言保持，但分段跑（每 act 校验，不整片等）                                      |
| 引擎默认切 cosyvoice      | `app/services/voice.py`         | DEFAULT_ENGINE 已可切；正式生产切换 + 超长文本分批                            |

### 4.3 舞台编排（长视频不卡壳的关键）

- **TTS 不再整段一次性送**：20min 旁白 4,300 字分 ~6 段（每幕一段）合成，**幕内段落**用 CosyVoice 连读保证韵律，幕间允许自然呼吸。规避超长 TTS 超时/截断。
- **每幕独立断点**：任一幕跑完即 `state/` 落盘；卡住/改史实只重跑该 act，不重跑全片。
- **生图并行**：同一幕内场景派生 + 关键新图可 4–6 路并发（API 配额内）。

## 5. 落地路径（四步走，逐步验收）

> 与 TECH_DESIGN 的 M0–M5 对齐：当前约在 **M1–M2 之间**（单镜可重建已通，整条成片未验收）。

| 阶段               | 做什么                                                           | 验收                        | 新增成本     |
| ---------------- | ------------------------------------------------------------- | ------------------------- | -------- |
| **S1 概念验证(POC)** | 挑 1 个场景资产（如「未央宫朝堂」）做 3 机位派生 + 1 幕 ~90s 成片，验证"一图多用不腻"          | 90s 可看，画面无明显重复感           | ≈¥5–10 图 |
| **S2 单幕成片**      | 完整跑通 1 幕（4–6min，~70 镜头），含 TTS/align/场景派生/关键新图/Ken Burns/字幕/合成 | 4–6min 成片，通过该幕史实闸门 + 时序断言 | ≈¥40–60  |
| **S3 全片贯通**      | 3–4 幕拼接成 15–20min 单条，幕级断点续跑 + 分段时序断言                          | 全片可播，无音画漂移                | 复用 S2 资产 |
| **S4 平台化打磨**     | 横竖屏/分P/完播率：片头钩子、高潮分布、封面、BGM 版权、G1 全面过检                        | 达发布标准                     | 平台合规核对   |

**依赖顺序**：S1 → S2 → S3 → S4。S1 是生死线（验证场景复用在观感上是否成立），不过关则画面策略需重估。

## 6. 平台侧硬约束（发平台必须提前确认）

| 平台     | 关键约束                                   | 对方案影响                          |
| ------ | -------------------------------------- | ------------------------------ |
| B站     | 单条 ≤ 上限（普通约 4GB/长时间需分P）；横屏 16:9 常见     | 20min 单条可行；横屏 `1920×1080`      |
| 抖音/视频号 | **抖音单视频常规 ≤ 15min**（>15 需长视频权限/走合集），竖屏 | **15min 为安全上限**；竖屏 `1080×1920` |
| 完播率    | 超长视频完播率天然走低                            | 必须加钩子+幕内小高潮+分段小标题              |
| 版权     | BGM/字体                                 | 无版权古风库 + 思源宋体（SIL OFL）         |
| 时长与曝光  | >15min 的视频平台推荐权重可能不同                   | 视目标平台决定 15 or 20               |

> **建议**：**先按 15 分钟竖屏（1080×1920）** 定稿，兼容抖音；若主投 B 站再出横屏 20min 版。两条腿共用同一幕/资产结构，只是 compose 分辨率不同。

## 7. 内容与脚本策略（长片的隐藏瓶颈在文字）

画面能归并，**文字不能注水**。20min 需要 ~4,300 字有信息量的史实解说，这是最大的内容工作量：

- **旁白生成**：目前 script.py 只是切分，不产文。长片需要**章节化脚本**（每幕一个 md），建议：
  - 大纲 → 幕 → beat 三级；每 beat 一段落，段内句长 8–25 字由 script.py 保证
  - 每幕独立成稿、独立走 **G1 史实闸门**（人物/时间/事件核对），避免长片尾部史实硬伤
- **多音字/专名表是长期资产**：`config/polyphone.yaml` 持续积累（月氏 zhī、冒顿 mò dú、阏氏 yān zhī、龟兹 qiū cí……）——历史类账号的隐形门槛，长片尤其不能错
- **文→图对齐**：场景派生依赖旁白语义，需保证 `narration_text` 与 scene 匹配（如"朝堂议事"→朝堂资产），避免图文不符
