# 生图渠道与模型

2026-09-12 按用户提供的渠道能力更新。能力声明已接入调度，尚未调用新模型实测。

| 渠道 | 状态 | 支持模型 |
| --- | --- | --- |
| cxk | 启用 | gpt-image-2、gpt-image-2.5、gpt-image-2.5-flare、gpt-image-2.5-sunburst |
| aicost | 启用 | gpt-image-2、gpt-image-2.5-flare、gpt-image-2.5-sunburst |
| QC_YC（配置名 qcyc） | 暂停 | 保留旧配置与密钥，恢复时再启用 |

配置入口为 `app/config/config.yaml` 的 `image_channels`。复用 `.env` 中原有供应商密钥；模型名不再决定密钥的发现方式。修改配置后须重启常驻应用。

默认模型仍为 `image.primary.model: gpt-image-2`，避免全局改模型使已有图片缓存失效。新任务可在 `image_prompts.json` 的单张图片对象中指定 `model`：

```json
{"shot_001": {"en": "Historical landscape", "model": "gpt-image-2.5-flare"}}
```

未指定时沿用默认模型。单图模型同样适用于有参考图的任务；请求指纹包含模型，切换模型会产生新的缓存身份。供应商切换保持模型不变，不会暗中以其他模型代替。已有合格缓存直接复用，不需要渠道在线。

flare、sunburst 可以分配给 cxk 和 aicost；基础 2.5 仅发给 cxk。整批中若有待生成任务没有支持其模型的渠道，在任何生图请求之前阻断。QC_YC 不参加生成、失败回退和额度同步。

各供应商默认同时 1 个请求，两个供应商可并行；其所有模型共用这个上限。此限制在一个应用进程内共享，并非跨进程配额管理；请通过单一生产进程调度，避免同时启动多个独立生图进程。只有确认供应商额度允许后才调整 `max_concurrency`，新增模型不会被误算为新增密钥。保留现有全局请求频率控制、有限重试和逐次持久预算。

预期减少不可用渠道的等待和不支持模型的错误请求。各新模型的真实延迟、限流额度、价格及画质尚待有明确调用预算的实测；当前没有据名称假设 flare 或 sunburst 更快，也没有写入推测单价。
