## 🔴 一、本轮修掉的 P0（3 项）

### P0-1 ASR 回检把 SSML 源码当期望文本 —— **我上一轮引入的严重回归**
- **现象**：`_ac.check(gwav, gtext)`，`gtext` 是 `build_group_ssml()` 输出，含 `<speak>`/`<phoneme>` 标签
- **实测**：纯文本 21 字 → SSML 75 字（标签占 ~70%）。音频完全正确时 PER = **15.8%**（阈值 8%）→ 每组必判失败
- **后果**：每组触发「去 SSML 重合成」+「SSML 恢复」= **3 次 TTS 渲染** + 5 次 ASR 调用。批量 10 集 ≈ TTS 成本 ×3、ASR 2750 次、1650 行刷屏告警
- **根因**：期望文本应该是「TTS 实际念出的内容」，不是 SSML 源码
- **修法**：新增 `_group_spoken_text()` = 纯文本 + 已应用的 replace；回检 7 处全部改用
- **验证**：修复前 15.8%（误判）→ 修复后 **0.0%**（正确通过）

### P0-2 ASR 临时文件固定名 → 4 线程并发互相覆盖
- `asr_check.py:69` 固定 `hv_asr_16k.wav`，paragraph 档 `workers=4` 同路径读写 → **听写串台**
- 修法：`pid + uuid` 唯一命名

### P0-3 TTS 成本台账生产路径从未调用
- `_tts_record_cost` 只在 `voice.py` 的 `main()` 里调（line 1002），`produce → synthesize()` **零调用**
- 批量 10 集 TTS 花费零记录；`state/tts_cost_ledger.json` 根本不存在
- 修法：移进 `synthesize()`

### P0-4（功能缺口）无批量编排
- 全仓 CLI 无 batch/queue；单集 `produce` 失败即抛 → shell 循环第 3 集挂掉整批停
- 无任何「跑完哪几集」的状态文件 → 中断后全靠人肉回忆
- 修法：新增 `hv batch`（见下）

## 二、新增能力：`hv batch`

```bash
hv batch --file eps.txt                          # 串行跑多集，单集失败继续
hv batch --file eps.txt --stop-on-error          # 首集失败即停
hv batch --file eps.txt --resume --batch-id X    # 断点续跑，跳过已完成
hv batch --file eps.txt --stage tts,compose,verify
```

- 状态文件 `state/batch_<id>.json`：`total/done/failed/pending`，**每集落盘**
- 单集异常捕获后继续（失败隔离核心）
- `--resume` 读状态文件跳过已完成

## 四、建议的批量首跑姿势

```bash
# 1. 小批次验证（2~3 集）
hv batch --file eps.txt --stage tts        # 先只跑 TTS，看回检有无误报、成本台账
hv cost                                     # 确认花费
# 2. 确认无误后全量
hv batch --file eps.txt
# 3. 中断后续跑
hv batch --file eps.txt --resume --batch-id <上次的 id>
```

**首跑请盯一次屏**：确认 ASR 回检不再刷屏误报、成本台账有记录、单集失败后确实继续跑。
这三件事确认完，就可以放心挂机了。
