# 抖音历史视频制作规范（2026-11-05）

普通新底图共用已启用渠道的全部常规模型，根据渠道并发容量分配，在可用型号间分摊任务。实际派发时，哪个渠道先空出位置，就从队列中取一张它能处理的图，优先接手只能由该渠道生成的镜头。人物、参考图和道具插镜均可参加。实际推近达到 1.6 倍时使用可用的 4K 型号。手动指定型号、已审核请求、已付费底图仍按原绑定处理。相同请求去重，未知结果沿用既有恢复流程。

渠道近期失败率过高时暂停派发；最近一次结果满一分钟后，允许以单个队列位置发送尚未发出的新画面验证恢复，连续两次成功后恢复配置并发。恢复失败仍计入原预算并重新冷却。健康渠道持续接单；冷却渠道保留在队列中并定时唤醒检查，不能因批次启动时不可用而整批永久排除。已拒绝、未知结果和已收到响应的请求继续遵守原有停止与恢复规则，不用于恢复探测。

外部录音对齐后，可在制作页按旁白段定位，导入同声线 WAV 补录自然短句，试听接缝后选用新母带，再直接启动原有的旁白或视频任务。完整听看时可定位全部旁白段。分幕语气提示随完整听看核对。录音前按与字幕相同的故事正文提取旁白，原始稿和已经冻结的版本保留。

依据用户本轮整改指令，本文件是 hv-studio 当前流程规范；与复制的 Writing-DNA v5 研究型流程冲突时，以本文件为准。原项目 D:/hv 的规则和素材不改动；旧规则可作参考，不再作为本工作台的强制逐句考据协议。

默认流程：写稿并核实关键事件 → 配音 → 配图字幕 → 完整听看、修改、确认导出。样片按需要使用，新声音或新表现手法可先试听试看，成熟系列不强制每集做视频样片。

实际视频任务先完成音频复用、切分、质量与对齐，再进入图片阶段。图片可独立生成，但不把无效音轨留到补图之后才发现。制作页允许将已有底图用于多个镜头；旧提示词提案不加入当前分镜必备清单。未作镜头安排时的自动逐段建议只是初稿，不要求每段购买新图。

图片预算统一表示总尝试次数；旧参数 image_retries 仅兼容为总上限的增量，不代表另一个重试专用池。预检与调度按同一组去重请求计算，已收到响应先恢复。部分成功即时登记，失败同样显示已耗额度。内容策略拒绝和结果不明的读取超时保留停止原因，不自动原样换路重发；503 渠道短暂冷却，不让整批连续撞同一故障。

已确认与未确认使用统一的当前候选判定，历史交付记录不能让当前待处理问题显示绿灯。对齐未执行不能显示为无问题；制作页提供单独重对齐和母带范围调整入口，不用增加审批表解决技术问题。

关键事件须有可靠依据，人物、时序、地点和结果不能张冠李戴。影响结论的数字要核对；争议不写成定论，非原文转述不伪装古人原话。确认人记录实际核查结论。详细来源按事件或按幕选填，不强制 claim_id、逐段证据、反证表、原典逐字数字对应或写前核查表。软件不声称能自动判断史实真假。

用通俗白话讲清事情，允许合理的场景示意和修辞，不虚构决定性事件。标题可独立拟定，但须忠于内容。画面不要求每个动作有独立原典，保留既定画风，不篡改文案。

创作卡、节点作用和新信息为编辑辅助；史实确认不再等待分镜完成。候选制作前须对当前正文作绑定关键事件确认；确认记录只代表当前正文的事实与故事基准，不替代候选成片听看。合成新旁白需要所选声音与明确预算；用户提供的完整母带直接进入本地切分与对齐，不要求填写合成音色资料。视频仍需实际图像、音轨、字幕和完整时间轴。空缺或不匹配媒体由技术检查拦截。

冻结导入快照继续核验；外部原稿/规则更新提示有新版本，不使已冻结版本失效。需要使用新版正文时显式导入，不自动更新。非媒体编辑备注不触发整套复审，正文、声音及画面变化仍检查对应版本。历史批准不复制到新稿。

史实确认绑定正文，选声音、配图不撤销已确认的正文。音轨校验绑定正文、声音合同、实际请求和速度处理，不以分镜变化为由重配音。旧审核记录保留原范围，不自动扩大授权。一张底图可连续覆盖多个段落，仅在需要换画面时新增节点；生成时间轴仍完整覆盖旁白。普通手写草稿允许不分幕，修订保留原字，不自动添加幕标题。

预算、失败和不确定请求计数、缓存身份、源稿音轨字幕一致、采样与帧数、字幕安全区和真实人工听看继续保留。保留原稿、原始录音、旧成片和图片缓存。v2 与 legacy-preview 各自继续使用；不向 v2 移植多音字替换或 legacy 镜长上限。

生成图是底图，不是视频帧。1024×1536、1086×1448 等可正常解码的图片不因尺寸不同而重抽；使用既有等比放大和裁切输出 1080×1920，原图保留。底图短边至少 256 像素，与既有素材复用规则一致；清晰度与裁切是否影响主体在看片时检查，不把技术可读当作画面已认可。已收到或隔离的响应先用 `bin/recover_image_receipt.py` 离线恢复，恢复不消耗新额度；不能恢复的响应保留证据，不能悄悄重试或重置已耗额度。

短样片使用整集外部母带时，在制作页试听并确定对应正文的起止时间，另存无损 PCM WAV 片段。记录原母带哈希、采样范围、片段哈希和当前正文，声音基准不变，原母带不覆盖。片段不再被当作无关的新音色；也不继承整集的试听批准。禁止用整集母带直接全局对齐短稿，不按字数猜测截取秒数。已有外部录音的“旁白候选”只做本地切分和对齐，不走新的配音服务。

工作台成片页处理具体语音与导演问题，完整听看后一次操作记录听审和看审、核验媒体并确认本地导出。不会自动上传平台。复盘从当前成片自动关联版本，须确认实际发布的是该版本；缺失数据留空。


## 2026-11-05 生产复盘补充

- 旧逐帧配音、旧云端合成与旧补图入口已删除；历史预览只读入现有媒体。正式付费生产使用 v2，诊断探针另存且受持久预算约束。
- 旁白单元画面采用 source_image_briefs.json 作为正式输入；storyboards 是生成输出。没有画面描述时不直接拿原始旁白付费生成。
- 新提示词的生成失败不能保留同名旧图为“已完成”；修改用图安排后重新核对时间轴。
- 语音识别仅使用本地 Whisper。旧云端识别分支及自动降级配音开关已删除。
- 所有测试默认使用临时作品与状态目录；不再运行修改真实历史素材后尝试恢复的测试。

## 2026-11-07 第四集运行整改

制作页显示当前任务的实际工序、单元进度、最近心跳与累计尝试；恢复使用原任务及预算。渠道统计异常独立记录，已收到的响应继续安装。离线恢复与正常安装使用同一套像素校验，并按原响应去重登记成本。旧回执仅在原预算中唯一匹配到成功请求时补记调用编号，不改原预算。

外部母带复用只做本地切分、质量检查和字幕对齐。事实确认绑定当前正文；同一授权不因刷新或恢复而重办。制作前已有音频与分镜时，先看每张底图连续覆盖的时长。语音识别疑点按类型与时间列出，人工实际听过后可以明确选择多段记录同一结论；确认口误仍须修订。完整听看与最终确认单独保存。

## 录音交付、分镜与修订

外部旁白可以交一份完整 WAV，也可以交按编号排列的 WAV。目录同时包含两者时，默认只用文件名明确的完整母带。也可以在制作页选择“使用编号分段”，或在 CLI 配合 --external-master 文件夹使用 --audio-mode parts。只有编号文件时自动按数字排序。重复编号、缺号、多份无法区分的母带会提示输入问题。每次任务只绑定其中一种交付。编号模式保留原文件和各段已有停顿，建立本地连续工作音轨，不额外插入静音。回执记录每份原音频的指纹和采样边界。

修订使用本集已绑定录音的相同采样区间。独立识别按音频、模型和参数复用，字幕对齐还要匹配原文和声学窗口。相交的剪口及会截断邻句的边界重算。先处理定位覆盖率低的段落，实际无法拼出完整可读字幕时报告原文单元和录音时间。

编排按剧情换景，母带时长用于预算和预览。单元数、编码分段数、底图数和画面变化次数分别统计。制作页展示最长连续同图时间、首尾旁白及画面描述，缺少时长或版本过期会说明原因。超过一分钟只提醒检查情节，每集用图数量由实际剧情决定。声学时间齐备时，制作页和后台读取同一组镜头边界。地图和后期字卡可标为 local_only，只接受已登记的本地画面。

完整视频任务在付费图片请求前本地核对片头和幕卡。分段渲染保留逐帧字幕高亮、动效和封装校验。同一次运行内，文件、输入与校验工具均相符时使用该次的完整解码回执。独立核验另行解码。后台记录工序时间、模型进程启动、缓存复用、图片排队和实际请求耗时。
