## 三、问题清单

### P0（严重，会真出错或真花钱）

**P0-1｜4 条测试用例被同名定义覆盖，永远不执行**
`tests/test_production_regressions.py` 里 `_install_fake_encoder` + 4 个 NVENC 用例被整段重复定义。
AST 复验：顶层 22 个 def，**4 组重名**（`test_nvenc_oom_downgrades_to_libx264`、

**NVENC 降级这条最贵的回归守卫，跑的其实只是副本**，"新增 22 条"含 4 条虚增。
建议：删 309-397 重复段；加一条"全仓 test_ 函数重名即失败"的守卫。

**P0-2｜`motion.py` 没同步 `compose.py` 的资源修复（同款问题只修了一半）**
- `motion.py:291` `img = Image.open(src_p).convert("RGB")` —— 无 `with`，逐镜泄漏 fd（`compose.py:505` 已改 `with`）
- `motion.py:333` `err = proc.stderr.read()...` —— 只读不关（`compose.py` 已有 `_read_stderr` 关流 + `finally` 兜底）
- `motion.py:334` `rc = proc.wait()` —— 无超时；`config.yaml:256 timeout_sec: 0` 默认不设超时 → **ffmpeg 卡死就永久挂起**
- `motion.py:331 except BrokenPipeError: pass` —— 不比较「已写帧数 vs 预期帧数」（`compose.py:526-532` 有此比较）→ ffmpeg 提前退出但 rc=0 时**静默出短片**
建议：motion 复用 compose 的 `_read_stderr`/`_wait_proc`；BrokenPipe 分支补帧数核对。

**P0-3｜分段续跑无「参数指纹」→ 改了参数却静默复用陈旧段**
`compose.py:860-865` 判据只有 `p.exists() and 帧数 == 预期`。
改字幕内容/样式、改 grade、改 cq/preset/编码器后重跑，**所有段全部跳过、成片内容纹丝不动**。
更糟的一条：`_HWENC_DISABLED` 在第 N 段降级为 libx264 后（compose.py:590-595 自承"前段硬件+后段软件混合"），
重跑时前 N 段仍命中跳过 → **混合编码被永久固化**。
建议：段文件名或段清单带 `hash(timeline + vcodec + subtitle_cfg + grade)`，不匹配即重编。

**P0-4｜合成后从不校验实际帧数，帧数断言只在 verify 阶段生效**
`compose.py:733` `assert_timing_or_raise(ep)` **不传 `video_total_frames`**，
而 `timing_assert.py:126` 仅在非 None 时执行第 5 项断言 →
只有 `orchestrator.py:407`(verify) 传参。**任何直接走 compose 的出片，帧数漂移 0 拦截。**
叠加 `compose.py:849/882` `n_actual = n_total_all` —— 打印的"实际帧数"其实是**预期值**，排错时会被误导。
建议：concat 后 probe 一次真实帧数并传入断言；`n_actual` 用 probe 结果。

`app/models/shot.py:95`，全仓零消费（`grep` 除定义处外无引用）。属整改遗漏，1 行删除、零风险。
