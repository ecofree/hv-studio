## 0. 结论

**工程底座能跑，产品流水线不能一键跑。**

- 环境、导入、14 个 pytest、已交付短片的 `verify` 都是通的。
- **从空白 `script.md` 到 mp4，没有任何一条命令能走完。** 设计里的 7 段流水线被拆成 3 套互不兼容的入口，中间最贵的两步（生图、分镜）不在统一编排器里。
- 当前用户感知的「跑不通」主要是：`laogongtuan` 正在用「4 分钟短片管线」硬编 **21 分钟 / 31487 帧**。进程没死，只是极慢；从 13:09 起 `episode produce --stage compose` 已跑 40+ 分钟，`.tmp` 仍在涨。

| 问题 | 严重级 | 一句话 |
|---|---|---|
| 三套入口、没有单一 DAG | **P0** | produce / run / shots+bin 各干一段，新片无法闭环 |
| 空集无法 produce | **P0** | schema 门在 script 之前，鸡生蛋 |
| 长片合成架构错误 | **P0** | 设计是 concat 预渲染段；实现是 Python 逐帧 rawvideo，21 分钟会看起来像死机 |
| 逐句 TTS 拼接 | **P0** | 设计明文禁止的路径，正是生产路径 |
| 状态机是演出 | **P1** | 已交付成片仍是 `draft`；8 态里只有 4 个会被写 |
| 生图/角色锁/字幕/对齐未接入主链 | **P1** | 服务文件在，编排器不用 |
| WebUI / API `/run` 会误导 | **P1** | UI 自称 M0 stub；`/run` 默认只 verify |

**不要杀** 当前 `python … produce laogongtuan --stage compose`（PID 35472）和配套 ffmpeg（PID 36748）。它们在干活。

## 2. 设计 DAG vs 实际 DAG

设计（`TECH_DESIGN.md` §4）：

```
script → tts(整段旁白) → align(强制对齐) → image → motion → subtitle(ASS) → compose(concat)
```

实际 `hv episode produce`（`orchestrator.py:144-188`）：

```
schema 门 ──► script(切句成 frames)
                 │
                 ▼
              tts(逐 frame 一段 wav)
                 │
                 ├── 无 shots → 跳过 compose，状态写成 SCRIPTED（TTS 完成也叫 scripted）
                 ▼
              compose(PIL 现场运镜 + 整句字幕)
                 │
                 ▼
              verify
```

**不在这条链上：** align、image、upscale、motion 预渲染、ASS、I2V、G1/G2 人工闸门。

### 2.1 三套互斥入口（总根因）

| 入口 | 命令 | 实际职责 | 出片？ |
|---|---|---|---|
| A 编排器 | `episode produce` | script / tts / compose / verify | 仅当 **shots 已存在** |
| B 单镜管线 | `episode run` | 默认 **image + motion** | 仅 `--only SHOT --compose`；全片 run **不会合成** |
| C 分镜引擎 | `episode shots` | 读 `scene_plan.json`，把多帧绑到已有底图 | 否 |
| D 历史脚本 | `bin/m2_*.py`、`batch_generate_lgt.py`、`rebuild_laogongtuan_plan.py` | 真正把汉武系列和 laogongtuan 做出来的路径 | 视脚本而定 |
| E API `/run` | `POST /v1/episode/{id}/run` | **默认只 verify** | 否 |
| F WebUI | `episode webui` | 渠道分数 + 多音字玩具，文案仍写「9 个 service 是 stub」 | 否 |

`--stage` 在 A 和 B 里含义不同：produce 是 `script|tts|compose|verify`，run 是 `image|motion`。同一 CLI 旗标，两套语义。

### 2.2 生图有两套模型，混用会毁片

1. **pipeline `stage_image`**：一镜一图，写入 `shots/{shot.id}.png`，prompt = `shot.prompt or shot.narration`。
2. **shot_builder / batch_generate_lgt**：几十张场景底图，多句共用；`shot.prompt` 甚至是 `[LGT01]` 这种占位。

`episode run --force` 跑在 shot_builder 产物上，会按镜重画并改写 `image_path`，**拆掉场景复用**。

shot_builder **要求 PNG 已在磁盘**（`shot_builder.py` 缺图即拒绝）。pipeline **要求 shots 已存在**。produce **既不生图也不装配 shots**。三步互相等对方先做。

## 3. P0：流程设计缺陷（会让人觉得「跑不通」或出片错）

### 3.1 没有「剧本 → 成片」的单一编排

新片今天真实步骤（任何一步不在 CLI 里都要手搓）：

1. 手写 `episodes/{id}/script.md`
2. `episode init`（空 json）
3. **绕过 produce**：`python -m app.services.script … --episode {id}`（否则 schema 门拦住）
4. `produce --stage tts` 或 `python -m app.services.voice`
5. 另写 `image_prompts.json` + 一次性脚本生图（laogongtuan 用的是根目录 `batch_generate_lgt.py`，硬编码 `D:/hv`）
6. 手写或用 `rebuild_*_plan.py` 生成 `scene_plan.json`
7. `episode shots {id}`
8. `produce --stage compose --stage verify`

这不是流水线，是作业手册。`orchestrator.py:17-18` 把分镜写成「人工创意、不在自动链内」——对 4 分钟 60 镜勉强成立，对 365 镜长片就是把最容易错的步骤推出系统。

### 3.2 空集被 schema 门卡死

`validate_schema`：无 frames 且无 shots → 非法。  
`produce` 先校验再 `stage_script`。  
`init` 产出的正是这种空集。  
**官方入口无法启动官方第一步。**

### 3.3 默认可对已有集「重切脚本」

`stage_script`：若已有 frames **且** shots，走 `rebuild_frames`（按 `frame.id` 对齐旧音频）。切分规则一变（今天刚修过 `split_long_sentence`），新 id 对不上旧 shot → 下一轮 schema 才爆 dangling。校验在重建**之前**，本轮 compose 可能 KeyError 或配错音画。

对 laogongtuan 执行无 `--stage` 的 `produce` 尤其危险：会重切 365 句 + 重 TTS（钱）+ 重合成（小时）。

### 3.4 TTS：设计禁止逐句拼接，生产就是逐句拼接

设计 §4.2 / §13：「绝不能逐句 TTS 再拼接」。  
`voice.synthesize` 按 frame 循环；compose 把 wav 加 100/150ms pad 拼成 `narration.wav`。  
`voice.py` 模块注释仍写「强制整段生成」。

后果：句与句之间韵律重置，正是设计要避免的「念清单」。长片 365 段会更明显。`alignment.py` 存在但 produce/compose **从不调用**；字幕按整段音频窗口烧，不是字级卡拉 OK。

### 3.5 compose 不能扛长片

设计 §4.7：每镜 motion mp4 → concat 无重编码 → 混音字幕。  
实现：Python 打开 1882×3344 `@2x`，逐帧 crop/resize/画字幕/`tobytes()`，stdin 喂 ffmpeg。hw-002（5 分钟 / 7475 帧）能熬；laogongtuan（21 分钟 / 3.1 万帧）变成小时级、低 pagefile 上 historically MemoryError。

附加风险：`Popen(..., stderr=PIPE)`，stderr 要等全部帧写完才读。`-v error` 多数时候没事，一旦 NVENC 刷屏就会经典管道死锁。`timeout_sec: 0` = 永不超时。

### 3.6 API `script_md` 是陷阱

`produce(..., script_md=)` 写入 `ep.notes`，只用 notes **决定要不要跑** script。  
`stage_script` 读 `_load_script_md`，**不读 notes**。  
只靠 API 传剧本 → `无脚本内容`。

### 3.7 `episode run` 看起来像生产，并不出片

默认 stages `["image","motion"]`。`--stage compose` 打印「未知 stage」然后继续，**不失败**。全片 run = 付费生图 + 没人用的预览 mp4。

## 4. P1：状态、配置、能力都是「建了没接线」

### 4.1 三套状态机，没有单一真相

| 机器 | 位置 | 现实 |
|---|---|---|
| 设计 shot SM | pending→…→composed | 未实现 |
| `EpisodeStatus` 8 态 | `models/episode.py` | produce 只写 DRAFT/SCRIPTED/COMPOSED/FAILED，且直接赋值，绕过 `transition_to` |
| `Shot.stage` | pipeline 写 image/motion done | produce 不写 |
| `run_stage` | 线性推进 + checkpoint | produce **不调用**（cli 还 import 了它） |

磁盘事实：hw-001 / hw-002 / hanwu-ch3 / hanwu-feature 都有成片，json `status` 仍是 **`draft`**。laogongtuan 有全套资产，status = **`scripted`**。状态不能当完成度，也不能当计费依据。

`Shot.stage_ok` 是坏的 `@property`：还带 `stage` 参数，无法按属性调用。

### 4.2 配置声明 vs 运行事实

| 声明 | 运行 |
|---|---|
| `tts.primary_engine: qwen3-tts` + Kokoro 降级 | DashScope CosyVoice + edge-tts |
| `aligner: linear_estimate`（注释：MMS_FA 不能对齐中文） | 服务存在，主链不用 |
| `postprocess_upscale.engine: pil_lanczos` | 与代码一致（RealESRGAN 仍 NotImplemented） |
| `video.enabled: false` | 无 I2V 生产服务；`is_hero` 无分支 |
| `subtitle.*` 思源宋体 / 关键词花字 | `subtitle.py` 整文件 STUB；compose 自己 PIL 画整句 |
| `profile.bgm` | 代码已接线；`assets/bgm/` **空**，每次跳过 |
| `image.consistency.face_sim_threshold: 0.65` | pipeline 用 0.5；character_lock 用 0.45；无自动重试 |
| 根目录 `config/style.yaml` 等 | 死双轨，代码只读 `app/config/` |

### 4.3 人工闸门 G1/G2 不存在

设计 §11：史实校验、视觉抽检「不能省」。CLI/API/WebUI 都没有暂停点。长片史实面比 4 分钟短片大一个数量级。

### 4.4 角色一致性未进入当前生产路径

`character_lock` + insightface 在 pipeline `stage_image` 里。laogongtuan 走 `batch_generate_lgt.py` **纯文生图**。`assets/characters/` 空；仅 `resource/ref_packs/zhangqian/` 一份。365 镜共用 60 张场景图，人脸漂移没有闸。

### 4.5 资源约定落空

- `assets/bgm/` 空 → 永远无 BGM  
- `assets/fonts/` 空 → 字体写死 Windows 路径，换机即崩  
- `assets/characters/` 空  
- `cache/` 内容寻址：目录在，服务不按 hash 键缓存（设计 §9）

### 4.6 WebUI / README 漂移

WebUI 仍自称 M0 骨架。README 仍写「本仓非 Git」；仓库已 `git init`，HEAD `639b22e`。

## 6. 建议顺序（先改流程，再改代码）

不要继续给 A/B/C 三条链各打补丁。先定**一条** DAG。

**立刻（不改代码）**

1. 让 laogongtuan 这次 compose 跑完；不要 kill。预计还要数十分钟。若 tmp 长时间完全停止增长再查 stderr 死锁。
2. 不要对 laogongtuan 跑无 `--stage` 的 `produce`（会重切脚本）。
3. 不要对它跑 `episode run --force`（会按镜重画，毁掉 60 张场景复用）。

**止血（小改，让「新片能启动」）**

4. schema 门对「空集 + 有 script.md」放行，允许 `stage_script` 成为第一步。
5. `produce` 默认不要在已有 shots 时重跑 script；script 必须显式 `--stage script`。
6. `episode run --stage compose` 要么接上 `compose_episode`，要么直接报错退出，禁止「未知 stage」假成功。

**收口主链（真正让项目跑得通）**

7. 把「生图 + scene_plan + shots」收进 orchestrator，作为 `image` / `shots` stage；一次性 `batch_generate_*.py` 降为实现细节，不要当入口。
8. 长片 compose：按镜或按幕预渲染再 concat（回到设计 §4.7），或至少按幕断点续跑。21 分钟一条 rawvideo 管道不是可运维方案。
9. TTS：要么整段合成 + 对齐切镜（按设计），要么承认逐句方案并改设计/听感标准。现在是文档和代码互相否定。
10. 状态只由产物导出（有 wav / 有图 / 有 mp4），丢掉 8 态演出；WebUI 改成这条链的进度条，而不是 M0 玩具。

**不要优先做的**

- RealESRGAN / I2V / ASS 卡拉 OK / 第四套 CLI。主链没闭合前这些都是新双轨。

## 7. 一句话

hv 已经能把**做好的 json**编成可播的竖屏片，也已经用手工脚本做出了汉武 15 分钟。  
它还不是一条流水线：编排器只管切句、配音、合成；分镜和生图在仓库根目录的一次性脚本里；合成器按 4 分钟短片的逐帧管道在啃 21 分钟的 laogongtuan。  
所以「跑不通」不是环境坏了，是**流程被设计成必须靠人把三段拼起来，而第三段在长片上会跑到让人以为死机。**
