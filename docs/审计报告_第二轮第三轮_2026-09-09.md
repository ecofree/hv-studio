## 🔴 一、上轮修复引入的新问题（4 项，已全部修复）

**根因**：上轮用 `    ep = load(ep_id)` 做锚点插入锁与 `_produce_impl`，但该串**首次出现在 `reshot()` 体内**。

1. **P0-3 锁没生效**——锁被插进了 reshot，`produce()` 完全没加锁，双进程同跑一集仍会互相覆盖
2. **`reshot()` 报废**——函数体被截断，剩下的部分引用 produce 的 `stages/tts_fallback` 等参数 → `NameError`，**单镜重建功能 100% 触发**
3. **`_produce_impl` 张冠李戴**——签名是 produce 的，函数体是 reshot 的（引用非自身参数的 `keys/do_verify`）
4. **P2-3 遗留 NameError**——告警文案引用未定义的 `main`（`engine_report` 不返回 main），混引擎时 TTS 全部合成完、落盘后才崩，整轮白跑

**修法**：orchestrator.py 回退到补丁前，改用**装饰器** `@_with_episode_lock` 加锁（完全不动 produce 函数体），reshot 恢复原状。

**验证**（逐项断言）：
- `produce.__wrapped__` 存在 → 锁装饰器已生效
- `reshot` 签名 = `['ep_id','keys','do_verify']`，函数体无越界引用
- 两处 prompt 常量一致

## 三、第三轮：新领域（第一轮没碰过）

### 已修 4 项

1. **`read_wav` 标度契约**（P1，今日踩坑 2 次的复发根因）
   docstring 写「float32 单声道」实际返回 **±32768 原始标度**。我按 `[-1,1]` 直觉写 clip → 波形削成方波 → 当天所有 ASR 结论作废。
   修法：docstring 钉住标度 + 新增 `read_wav_float()`（除 32768）+ 3 例测试（含"读数写回不削波"回归）。全仓 4 个调用点核验当前均安全。

2. **`_grp_*.wav` 永不清理**（P1）
   voice.py 注释称「hv clean --build 会收走」，但 BUILD_DIRS 的 `"audio"` 指 `build/audio` 子目录，**永远到不了 `episodes/*/audio`** → 实测每集残留 55 个 / 28M。
   修法：cleanup 加 `AUDIO_TMP_GLOBS`，且在 build 存在性判断**之前**收集（否则无 build 的集被提前 return——我第一次就插错在这）。

3. **磁盘预检**（P1）— produce 开头 `_check_disk_space`，分级：<800MB 硬拒（防渲到一半磁盘满出半截片），800~2500MB 只告警（低磁盘机器不该一刀切）。

4. **TTS 成本台账**（P0）— 生图有 `cost_ledger`，**TTS 侧此前零记录**：出了 6 遍片子花了多少钱无法回答。新增 `_tts_record_cost` 写 `state/tts_cost_ledger.json`（ts/ep/model/chars/ok），写坏绝不阻塞生产。
