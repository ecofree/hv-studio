# xlc-01 文案交接入口

2026-10-19：史实与口播修订候选，固定画风、人物、旁白音色继续沿用。

`current.json` 指向本轮文案版本及可供现有 narration CLI 使用的计划。当前权威正文在 `revisions/3a0df0dd1f32ac8f1d4f/source.md`；新版共8段落组、46段正文。旧成片使用的 `episodes/xlc-01.json`、`script.md`、`script_narration.md` 和旧音频/图像均保留原绑定，未自动切换到新稿。

## 文件职责

| 文件 | 用途 |
| --- | --- |
| `source.md` | 含导演标注的唯一创作源稿；修改时导入一个新版本 |
| `narration.md` | 从第一幕起提取的正文源，仍含标注，供 v2 parser 使用 |
| `spoken.txt` | 纯朗读预览；不作为第二份可编辑权威 |
| `document.json` | 正文单元、原文映射、排除范围和导演标注 |
| `directions.json` | 语气/画面/停顿的原文、类型、单元锚点、字符位置与待执行状态 |
| `manifest.json` | 六份载荷的SHA-256、版本身份与候选状态 |
| `extraction.json` | 前置创作资料与正文的起止范围 |

计划还绑定 `writing_handoff`。准备计划、计算生成量、实际配音前均检查该版本；不能修改正文、删除清单或改写导演标注后继续复用旧计划。语气只是导演要求，是否能编译成引擎指令由既有音色能力决定；画面说明不冒充已执行的声音指令。

## 修订方式

在项目根目录运行：

```powershell
.venv-core/Scripts/python.exe bin/setup_episode_from_writing_dna.py --ep xlc-01 --src <新源稿路径>
```

此操作仅创建新文案版本、旁白计划和 editorial 指针，不调用模型，不覆盖已交付剧集的帧结构。输入使用 `### 【第一幕：标题】` 等幕标题。`【语气：平静】`、`【画面：宫门远景】`、`[停顿0.5秒]` 与 `[pause=0.5s]` 会单独保留。普通括注照读；未知或声音说明夹台词的标注需先改写，例如将 `（语音压低10%，带对讲机混响：好家伙。）` 拆为明确的导演要求和独立正文“好家伙。”。

后续录制沿用原旁白音色，需要先按项目规则建立明确预算，或走原有外部录音导入流程。新录音要重新对齐，新镜头要按新正文映射；旧84秒动画样片不能被当作新文案的成片证据。事实复核、声音试听、艺术判断与发布状态分别记录。

完整逐幕前后对照：`state/content-refactor-20261019/review/comparison.html`。主张台账、段落映射、研究者复核及技术证据在 `state/content-refactor-20261019/`。
